# Green Atlas — контекст для новых задач

Сначала прочитайте `HANDOFF.md`, затем **действующий контракт направления**
`docs/architecture/autocad-contract.md` и реестр разрывов
`docs/audits/2026-09-22-cad-pipeline.md`.
Основной и единственный развиваемый вход: открытый DWG/DXF в AutoCAD → плагин
→ локальное приложение Green Atlas. Хранение и расчёты локальные. AutoCAD не
является необязательным REGION-provider. Прямой upload через ezdxf, старые
конвертеры и DXF-only flow — совместимость, не альтернативная ветка разработки.
Не добавлять новый CAD-парсер/fallback. Решение 25 сентября заменяет обязательные
запросы в AutoCAD для каждой посадки: AutoCAD читает/восстанавливает исходник,
затем единый локальный проверяющий модуль работает по сохранённой геометрии.
Действующий срез: `docs/implementation/2026-09-25-prepared-geometry-placement.md`.
Ручная/автоматическая посадка, сохранение, повторная проверка и паспорт должны
использовать один подготовленный снимок и правила. Контуры отображения без
указанной точности нельзя автоматически объявлять расчётной геометрией.
Старый импорт не возвращать. Код ветки и реально запущенный API различать;
новая реализация проверена отдельно, пользовательский стенд ещё не переключён.
Пропуски отдельных объектов/ссылок должны оставлять доступную работу с явными
замечаниями, без выдуманной безопасности и без снятия проверок целостности.
Перед CAD-изменениями: `python3 scripts/architecture/cad_dependencies.py --check`.
Baseline legacy-связей нельзя расширять ради зелёных тестов.

Исторический перенос Mac: `docs/implementation/2026-09-17-mac-autocad-handoff.md`
(M3 Pro, AutoCAD for Mac 2027.0.1); предыдущий ПК:
`docs/implementation/2026-09-16-pc-dxf-handoff.md`. Их DXF-only/optional-provider
формулировки не переопределяют текущий контракт. Кустанайская — пример,
не исключение из общего сценария. Исторический оставшийся объём описан в
`docs/implementation/2026-09-10-remaining-scope.md`, локальный запуск Windows —
в `docs/implementation/windows-local-runtime.md`, выкладка — в
`deploy/adminvps/README.md`.

В Windows перед командами разработки обязательно выполняйте
`. ./scripts/windows-env.ps1` из корня репозитория в той же PowerShell-сессии.
Это относится к установке, сборке, проверкам, тестам и прямым запускам Node/Python:
временные файлы и кеши должны оставаться на диске checkout (здесь D:), не на C:.
Для нового вызова shell префикс повторяется; отдельный вызов скрипта не меняет
окружение других сессий. Из подкаталога используйте абсолютный путь к скрипту.
`windows-dev.ps1 -Action Start` применяет настройку для дочерних серверов сам.
Не запускайте тяжёлые проверки при нехватке места; существующие процессы
получают новое окружение только при явном перезапуске.

На 11 сентября тестовая площадка была выложена на AdminVPS. Агент на ней
отключён по просьбе пользователя до подключения API модели. Это исторический
срез, а не проверка текущего состояния сервера. Задачи по собственному агенту,
внешнему MCP и дальнейшему дизайну остаются в handoff; новый запрос пользователя
определяет текущую работу.

История отдельных чатов не заменяет документы проекта. После существенных
изменений обновляйте соответствующий handoff, чтобы следующие задачи могли
продолжить работу с проверенного состояния.
