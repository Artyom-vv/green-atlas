# Green Atlas — контекст для новых задач

Сначала прочитайте `HANDOFF.md`, затем актуальный перенос на Mac:
`docs/implementation/2026-09-17-mac-autocad-handoff.md` (M3 Pro, AutoCAD for Mac
2027.0.1; исследование ObjectARX, плагин ещё не реализован). Предыдущий срез ПК:
`docs/implementation/2026-09-16-pc-dxf-handoff.md`. Рабочий маршрут: полный комплект DXF → сервис → DXF;
DWG-датасет готовится заранее вне сервиса. Основной пример — Кустанайская улица,
не Парковая. Исторический оставшийся объём описан в
`docs/implementation/2026-09-10-remaining-scope.md`, локальный запуск Windows —
в `docs/implementation/windows-local-runtime.md`, выкладка — в
`deploy/adminvps/README.md`.

Основная локальная папка с 14 сентября 2026 года: `D:\current-projects\green-atlas`.
Ветка: `codex/field-audit-fixes`. Перенос 17 сентября сохраняет накопленные
изменения в Git; перед работой проверяйте status и сохраняйте последующие
незакоммиченные изменения пользователя.

В Windows перед командами разработки обязательно выполняйте
`. ./scripts/windows-env.ps1` из корня репозитория в той же PowerShell-сессии.
Это относится к установке, сборке, проверкам, тестам и прямым запускам Node/Python:
временные файлы и кеши должны оставаться на диске checkout (здесь D:), не на C:.
Для нового вызова shell префикс повторяется; отдельный вызов скрипта не меняет
окружение других сессий. Из подкаталога используйте абсолютный путь к скрипту.
`windows-dev.ps1 -Action Start` применяет настройку для дочерних серверов сам.
Не запускайте тяжёлые проверки при нехватке места; существующие процессы
получают новое окружение только при явном перезапуске.

На 11 сентября тестовая площадка была выложена на AdminVPS. Агент на ней
отключён по просьбе пользователя до подключения API модели. Это исторический
срез, а не проверка текущего состояния сервера. Задачи по собственному агенту,
внешнему MCP и дальнейшему дизайну остаются в handoff; новый запрос пользователя
определяет текущую работу.

История отдельных чатов не заменяет документы проекта. После существенных
изменений обновляйте соответствующий handoff, чтобы следующие задачи могли
продолжить работу с проверенного состояния.
