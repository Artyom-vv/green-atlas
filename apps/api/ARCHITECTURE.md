# Архитектура локального API

`app/composition.py` создаёт ресурсы и связывает сценарии. `app/application.py`
остаётся фасадом; предметные правила и кеши принадлежат отдельным модулям.
HTTP получает приложение через зависимости. Контракт маршрутов —
[OpenAPI](openapi.json).

| Модуль | Ответственность |
|---|---|
| `projects` | Библиотека, жизненный цикл и паспорт проекта |
| `cad_bridge`, подготовка источника | Приём AutoCAD, целостность, решения и снимок |
| `operations` | Долгие задания, прогресс, отмена и публикация |
| `geometry` | Подготовленное основание и геометрические запросы |
| `planning` | Оценка, предпросмотр, применение и квитанции посадок |
| `planting_zones`, `history` | Участки, Undo/Redo и согласованная запись |
| `validation`, `regulations` | Повторная проверка и версионированные правила |
| `species` | Ассортимент и отдельные профили растений |
| `scene`, `rendering`, `location` | 3D, Blender и подтверждённое окружение |
| `exporting` | Выходные файлы и отдельный CAD-выпуск |

Один подготовленный снимок обслуживает ручной/автоматический путь и повторную
проверку. Кандидат не читает новое состояние в середине предпросмотра.
Применение проверяет ревизии и основание, запись согласована с историей.
Инвалидация выполняется после успешного commit; конфликт не удаляет сохранённые данные.

Контракты принадлежат предметным модулям, общий файл содержит совместимые
экспорты. Клиент TypeScript генерируется, не правится вручную.
Legacy DXF-reader/writer сохраняются только для совместимости проектов;
нового HTTP-импорта DXF/ZIP нет.
