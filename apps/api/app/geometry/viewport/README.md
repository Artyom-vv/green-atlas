# Окно отображения

`IndexedGeometryQuery` сохраняет общий детерминированный отбор, бюджеты объектов,
координат и байтов, правила масштаба и топологическое упрощение. Эти представления
не являются расчётной геометрией посадки.

Для внешнего снимка `ProjectDisplayGeometryReader` открывает проверенный
производный SQLite/WKB/RTree. RTree выбирает кандидатов окна; точные binary64
границы исключают ложные попадания его float32-ячеек. Краткие признаки читаются
пакетами. Для упрощения читаются полные свойства без координат и временная
GEOS-геометрия; точный Feature восстанавливается, когда упрощение не требуется
или вернуло отказ. Готовые упрощённые координаты переиспользуются без повторного
декодирования WKB. Полная FeatureCollection и второй STRtree не создаются.
Старые inline-снимки и провайдеры без этого порта сохраняют прежний совместимый
путь чтения.

Отбор дискового окна читает краткие признаки один раз и временно сохраняет
только ordinal, строку ранга и группу в пределах 16 МиБ. Если окно превышает
этот предел, временные записи освобождаются и используется прежний второй
проход ранжирования. Результаты отбора кешируются отдельно: до восьми наборов
с общим учётным пределом 8 МиБ. В них остаются компактные массивы ordinal и
групп, без идентификаторов и словарей исходных объектов. Ключ учитывает весь
найденный набор, видимость запретных областей и число кандидатов. Попадание
пропускает чтение метаданных для отбора; полный обзор при необходимости
по-прежнему использует все подходящие записи.

Долгоживущий индекс содержит идентичность ресурса и ограниченные кеши размеров,
упрощённого отображения и SVG. Открытый reader принадлежит запросу через
`ContextVar`; выход, исключение и отмена освобождают его. Каждый повторный запрос
снова проверяет действующий источник и ресурс перед использованием кеша.
Отмена ожидания подготовки другим запросом не отменяет его общую проверяемую
сборку ресурса.
Общий lock индекса удерживается до заключительной проверки ресурса. При отказе
очищается сам объект кеша, включая ссылки уже ожидающих запросов: частично
проверенные размеры, SVG и упрощённые координаты не попадают в следующее окно.

Обзор при усечении обходит все подходящие объекты окна потоково. Дисковый путь
кеширует строки SVG по стабильному ordinal и масштабу, без GEOS, reader или
callback: до 120 000 записей с учётным пределом 32 МиБ. Короткие сегменты и
простые малые кольца переиспользуют путь между масштабами; точки и остальные
контуры учитывают масштаб. Попадание не декодирует WKB. Большое окно сверх
предела записей использует готовые пути, но не вытесняет рабочий набор новыми.
В обычном окне подходящие записи защищены от вытеснения последовательным
сканированием; новые пути занимают только свободный бюджет. Отдельный кеш
готового рисунка сохраняет прежние пределы четырёх записей и 24 МиБ.
Это пределы удерживаемых данных кеша, а не обещание полного расхода RSS.
Порядок обхода RTree
зафиксирован исходным ordinal: порядок независимых SVG-путей внутри одного
стиля может отличаться от обхода прежнего STRtree, сами пути, отверстия и стили
сохраняются. Бюджет обзора и признак неполноты остаются явными.

Подготовка 3D использует тот же проверенный ресурс и читает только поверхности,
подтверждённые древесные символы и бордюры по прежним условиям. Это работает и
при явном открытии 3D до первого окна карты. Полная коллекция не используется
как резервный путь для дискового ресурса.
