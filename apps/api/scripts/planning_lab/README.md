# Независимый стенд озеленения

Тонкий файловый запуск существующих `PatternApplication`, `RecommendationApplication`,
`ChangeSetApplication`, `ShapelyCandidateGenerator` и `ShapelyGeometryEngine`.
Поддерживает row/fill/mask и рекомендации с подбором пород по категории территории.
Не включает новый алгоритм размещения, CAD-парсер, HTTP, карту или подключение
к рабочей БД. В стенде не реализованы apply/undo и привязка
артефакта к продуктовому DXF-выпуску.

## Запуск

Из `apps/api` на Windows:

```powershell
. ../../scripts/windows-env.ps1
.venv/Scripts/python.exe -m scripts.planning_lab ../../fixtures/planning-lab/network-crossing.json --output ../../.runtime/planning-lab/first.json
.venv/Scripts/python.exe -m scripts.planning_lab ../../fixtures/planning-lab/network-crossing.json --output ../../.runtime/planning-lab/second.json
.venv/Scripts/python.exe -m scripts.planning_lab.compare ../../.runtime/planning-lab/first.json ../../.runtime/planning-lab/second.json
```

На Mac/Linux из `apps/api`: заменить `.venv/Scripts/python.exe` на
`uv run --no-sync python`, PowerShell-строку не выполнять. Используется
существующее окружение проекта; новые зависимости не нужны.

Каждый путь результата должен быть новым. Публикация выполняется атомарно
через hard link временного файла в том же каталоге и никогда не заменяет
существующий отчёт. Неподдерживающая hard links файловая система даст ошибку,
а не частично опубликованный отчёт. Файлы остаются локальными.

Коды выхода: 0 — сценарий завершился (включая ноль посадок), 1 — отклонён
существующей проверкой данных/версии, 2 — неверный вход или ошибка файлов.
Неожиданная ошибка программы завершает процесс с traceback; её нельзя считать
обычным нулевым результатом. Завершение сценария не означает нормативную приёмку.

## Вход

`PlanningCase` содержит полный зафиксированный Project с аналитической geometry,
plan, участками, слоями и типизированными сетями; запрос существующего pattern;
единицы `m`; происхождение `synthetic` или `normalized_source` и пояснение.
Исходный DXF здесь не читается. Снимок берётся из существующей подготовки либо
передаётся Mac-сессией после квалификации CAD-геометрии.

`scenario: "recommendation"` выбирает `RecommendationCase` с тем же снимком
и существующим `RecommendationRequest`. Отсутствующий `scenario` по-прежнему
означает pattern. Необязательный `request.territory` содержит category, regime
и основание basis; без него сохраняется прежний вид пресета. Примеры и измерения:
[подбор пород](../../../../docs/implementation/2026-09-17-species-selection/README.md).
Каждая альтернатива проходит настоящий генератор и проверку; в отчёт попадают
все завершённые проверки, в confirmable preview — только выбранный вариант.
Теперь request.plant_kind="shrub" включает подбор кустарников и требует territory.
Отсутствующее поле либо null оставляет прежний режим деревьев. В basis также
сохраняется полный снимок JSON-ассортимента, поскольку хеш Python-файлов не
идентифицирует изменения табличных данных.

Идентификаторы и временные метки снимка должны присутствовать явно: случайные
defaults Project/Plan/объектов для JSON-входа отклоняются. Идентичность включает
весь валидированный вход, в том числе source SHA, если он присутствует,
mapping, контекст сетей, координаты, версии и seed. `units=m` является явным
утверждением автора снимка, не автоматической проверкой масштаба CAD.
Отсутствующий source SHA не восстанавливается по имени файла.

Сохранены guards `source_review` и версии плана; стенд не снимает их. Снимок
копируется в память, любые вызовы save/apply в этом контуре запрещены.
Предпросмотр не создаёт ни посадок в пользовательском проекте, ни операций API.

## Результат и сравнение

Один JSON содержит:

- полный вход и его SHA256;
- хеши фактического Python-кода checkout, версии Python/GEOS/зависимостей,
  снимки каталога, реестра и профиля требований;
- фактические запросы генератору после изменения шага, квот и числа альтернатив,
  хеши областей генерации/направляющих и все возвращённые кандидаты;
- все завершённые проверки change-set: операции, координаты, статусы и полный
  `rule_trace`, включая отказы и заключительную повторную проверку;
- итоговый PatternPreview либо RecommendationPreview с альтернативами и источниками;
- отдельные измерения времени сценария, генератора и проверок.

`content_sha256` исключает время выполнения. `result_sha256` дополнительно
исключает basis, позволяя сравнивать одинаковый вход после оптимизации кода.
`compare` проверяет целостность обоих отчётов, сравнивает содержимое и сообщает
об изменении input/basis. Код 0 означает тот же вход и результат, не актуальность
норм или достоверность геометрии. Временные измерения не защищены content hash
и являются диагностикой, а не подписанным нагрузочным сертификатом.

Идентификаторы новых объектов и часы preview детерминированы только внутри
стенда; их нельзя использовать для apply в работающем API. Сравнивать реальные
ускорения следует по нескольким запускам на одной машине без тяжёлых соседних
задач; первый запуск индексов отделять от повторного.

`validation_evaluations` включает повторную проверку финальных кандидатов.
Это не число уникальных посадок. Исключённые safe-area области и бесконечное
множество возможных точек не выдаются за индивидуально проверенные отказы.
При ошибке записываются только завершённые вызовы с outcome=rejected; полнота
незавершённого этапа не заявляется. Нулевые результаты сохраняются без фиктивного
apply. Снимки/отчёты могут быть большими: здесь нет усечения до первых N объектов.

`applied=false` и `normative_acceptance=not_established` обязательны. В частности,
при неизвестной сети production-сценарий может вернуть ограниченный черновик
вне её контура; сохраняются data_confidence=limited и not_checked в trace.
Это не доказательство безопасности остальных мест относительно неизвестной сети.

## Проверки

```powershell
. ../../scripts/windows-env.ps1
.venv/Scripts/python.exe -m pytest tests/test_planning_lab.py -o addopts= -q
.venv/Scripts/ruff.exe check --config 'include=["*.py"]' scripts/planning_lab tests/test_planning_lab.py
.venv/Scripts/mypy.exe scripts/planning_lab
```

Тесты проверяют два свежих процесса с разными PYTHONHASHSEED, реальную сеть и
отказы, неизвестную сеть, эффективные настройки, отсутствие мутации/SQLite,
нулевые генерацию/результат, guards, целостность и запрет перезаписи артефакта.
Самостоятельный input fixture находится в `fixtures/planning-lab`; это явно
аналитический пример, не часть официальной улицы.
