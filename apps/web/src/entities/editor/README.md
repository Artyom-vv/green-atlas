# Проектное состояние редактора

`EditorSessionProvider` создаёт один vanilla Zustand-store для смонтированного
проекта. Маршрут ключует provider по project ID; серверные Query-данные и поля
RHF остаются у своих владельцев.

В store находятся инструмент, выделение и UI-состояние проекта: открытая
предметная панель, вкладка правой области, видимость левой/правой/нижней
областей, вкладка результатов, активный исходный слой и видимость слоёв.
Горизонт прогноза принадлежит текущему проекту и используется картой, сценой
и настройками выпуска.
Режим сравнения сохранённого плана (`editing`, `before`, `after`) также
принадлежит этому store; он не содержит копию плана или черновика.
Состояние 3D задаётся фазой `unmounted`, `hidden` или `visible` и кадром
для входа в сцену. `showScene` и `hideScene` меняют их вместе: скрытие
не смонтированной сцены не создаёт её, а уже открытая сцена остаётся
смонтированной при возврате в 2D. Отсутствующий новый кадр сохраняет предыдущий.
Renderer handle, непрерывная камера и Query-данные сцены в store не копируются.
Значения по умолчанию принадлежат `model/editorTypes`; таблица видимости
создаётся отдельно для каждого store.

UI-setters с `StateUpdate<T>` принимают готовое значение либо чистую
функцию текущего значения. `editorViewActions` вычисляет update внутри
Zustand-set, без копии React-state. Последовательные updater-вызовы используют
самое свежее состояние и не теряют соседние изменения видимости.
`setPlanComparison` принимает явный режим представления. Новый проект начинает
с `editing`; переключение сравнения не меняет инструмент и выделение.

`reset` очищает только инструмент и выделение. Вкладки, видимость областей,
слоёв и состояние 3D сохраняются, как раньше при локальном UI-state вне store.
`resetWorkspace` очищает представления при выходе из рабочего пространства,
сохраняя только горизонт при переходе к исходным данным того же проекта.
Provider над маршрутом ключуется project ID, поэтому другой проект и библиотека
получают новый store. Cleanup StrictMode сохраняет горизонт текущего проекта.
Автоматический переход tool → правая вкладка остаётся синхронизацией в
workspace model. Ширины, высоты и сохранение размеров принадлежат прежнему
layout-store workbench и сюда не перенесены.

Store-тесты проверяют выбор, независимость проектов, собственные таблицы
видимости, value/updater setters, допустимые фазы 3D и сохранение UI при reset.
