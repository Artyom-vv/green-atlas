# Подготовка исходных данных

`useSourcePreparation` владеет запросами проекта/паспортом/статусом, формой RHF и
переходом на карту. `usePreparationCommit` владеет командой сохранения настроек и
запуска. `readPreparationEvidence` проверяет восстановление по фактам текущего
API; он не выполняет запись.

```text
Форма → PUT mappings → подтверждённая версия → POST geometry → polling → карта
                          ↓ потерянный ответ запуска
                    GET project → GET latest → GET project
                          ↓ согласованная версия и источник
                    продолжить polling / явный повтор только POST geometry
```

Чтение считается согласованным, когда снимки проекта до и после latest имеют
одинаковые `state_version` и идентичность исходника. Настройки сравниваются
семантически, с независимым от порядка ключом layer/kind/visible. Операция
принадлежит подтверждённой основе, когда совпадают project ID, kind и
`project_state_version`. Завершение дополнительно требует свежей подготовленной
геометрии. Чужая активная операция или изменившаяся пара чтений оставляет запись
заблокированной.

При потерянном ответе PUT API не предоставляет отдельной квитанции этой команды.
Равные настройки на продвинувшейся версии подтверждают только текущее содержимое;
`MappingReceipt.evidence` различает `save_response` и `current_snapshot`.
Неизменная исходная версия не доказывает завершение потерянного PUT: интерфейс
показывает явное сообщение и повторное чтение, а не повторяет запись автоматически.
Гарантия атомарного снимка GET здесь не заявляется; изменение во время чтения
требует повторной проверки. HTTP API и его гарантии If-Match/CAS не менялись.

Recovery VM: `preparationRecovery?: { message, loading, onRetry }`. Пока он есть,
новая подготовка заблокирована. Повтор чтения не запускает новый расчёт. Ошибка
refetch при разрешении конфликта сохраняет исходный конфликт и черновик формы;
сброс выполняется только после успешного свежего запроса.

Проверки: 17 существующих сценариев SetupPage и 10 новых тестов контроллера/
восстановления формы прошли. Проверены потеря ответов save/start, совпадение
основы операции, отсутствие повторного PUT, меняющийся снимок, отказ чтения и
сохранение черновика при failed refetch.

Основания разделения этапов:
[TanStack mutation lifecycle](https://tanstack.com/query/latest/docs/framework/react/guides/mutations)
и [useQuery refetch](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery).
