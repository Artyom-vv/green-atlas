# Композиция рабочего пространства

`useWorkspaceModel` соединяет запросы проекта, контроллеры сценариев и состояния
представления. Его публичный результат сохраняет контракт `WorkspaceModel` /
`WorkspaceReadyModel`; он не является новым хранилищем серверных данных.

Выделенные обязанности:

- `useWorkspaceKeyboard` подключает один обработчик окна. Актуальные команды
  публикуются после React commit. Поля и модальные окна владеют своими клавишами;
  запрет команды не подменяется её выполнением.
- `useWorkspaceSelection` связывает выбор в дереве, на карте и в списке
  пересечений с существующими командами участков и редактора. Он сохраняет
  инспектор активной задачи и отменяет отложенное кадрирование при смене проекта
  или размонтировании. Хук принимает только необходимые значения, операции
  и handles карты / сцены.
- `workspaceToolPresentation` вычисляет подпись и подсказку инструмента без
  React, сети и изменения входных данных.
- `usePlanComparison` разрешает просмотр «До / После» сохранённого плана.
  Режим принадлежит существующему editor-store; запись, восстановление чтения
  и незавершённый жест рисования блокируют вход. Завершённый черновик сохраняется,
  но не входит в сравнение. Возврат и Escape меняют только представление.
- `useWorkspaceSceneSession` связывает камеру карты и 3D, сохраняет смонтированную
  сцену при возврате в 2D и читает снимок сцены через прежние Query options.
  Editor-store хранит фазу видимости и входной кадр; непрерывные изменения камеры
  принадлежат renderer handle/ref, без обновления store на каждый кадр.
  Горизонт принадлежит существующему editor-store текущего проекта и общим
  контроллерам прогноза. Чтение сцены начинается при явном открытии 3D и
  не зависит от готовности кадра карты. Возврат в 2D сохраняет viewer и камеру,
  но изменения плана, геометрии и горизонта в 2D не подготавливают новые сцены.
  Повторное открытие читает актуальный ключ плана, геометрии, исходника и года.
  Уже запрошенное представление завершается один раз и переиспользуется при
  быстром переключении режимов. Запрос нового горизонта откладывается на
  160 мс после последнего изменения. Отказ HTTP 409 или 422 для того же ключа
  автоматически не повторяется; кнопка повтора остаётся доступной.
  Сетевая или серверная ошибка допускает один автоматический повтор.
  Нормальный возврат в 2D переносит камеру.
  Выход из инструментов перед 3D и диалог несохранённого черновика остаются
  в координаторе; хук не принимает формы или полный WorkspaceModel.

Серверные данные остаются в React Query, проектные состояния представления —
в `entities/editor`, значения форм — в контроллерах соответствующих сценариев.
Горизонт сохраняется при переходе из рабочего пространства к исходным данным
и обратно, включая browser Back; смена проекта или выход в библиотеку сбрасывают
его. Остальные состояния представления рабочего пространства сбрасываются при
выходе из него через `resetWorkspace`. Ширины пристыкованных областей
принадлежат workbench layout. Скрытие области не отменяет её задачу.

Подбор по цели использует ручные параметры и общий выбор участков. Скрытый чат
и не подключённый текстовый разбор задания удалены. Обычный API расчёта экрана
вдоль зданий, адаптер его запроса и просмотр результата сохраняются; отдельного
перехода к этому режиму через интерфейс подбора по цели сейчас нет.

Первичное чтение проекта различает выполняющийся запрос, остановленное чтение
и недоступность native runtime. Остановленное чтение при доступном runtime
имеет явную кнопку повтора. Восстановление runtime обновляет только разрешённые
read queries, включая объекты карты, известный выпуск и завершающее чтение
подготовки. Мутации не повторяются.

Ошибка чтения объектов карты принадлежит `CanvasRecovery`: в существующем
стеке восстановления появляется действие повторного GET. Она не дублируется
общим диалогом ошибки записи. Предыдущая подложка и сохранённый план остаются
владением своих существующих Query/renderer, новый снимок состояния не создаётся.

Регрессионные проверки рядом с hooks покрывают владение клавиатурой, текущие
callbacks после commit, сохранение инспектора, блокировку выбора и lifecycle
отложенного кадрирования. Контракт сцены проверяет перенос и повторное открытие
камеры, независимость проектов, поздние ответы и задержку запросов горизонта.
Перенос этих обязанностей не меняет API, правила
геометрии или публичную композицию `WorkspaceReadyView`.

## Каталоги и новые владельцы

Корень содержит координатор, выбор и черновики размещения. `navigation`
содержит общую политику ухода и клавиатурные команды; `viewport` связывает
исходное представление, камеру, 3D и сравнение; `presentation` вычисляет
подписи и доступность без чтения или записи проекта.

`useWorkspacePlacementDraft` владеет формами и отменяемыми предпросмотрами.
Горизонт роста является локальной настройкой сценария и по умолчанию равен нулю.
Изменение настройки отменяет устаревшее предложение; новый расчёт начинается
по команде «Проверить места» и передаёт `scenario_horizon_year`. Проверка
не сохраняет горизонт, не меняет версию плана и не запускает запись проекта.
Он проверяет актуальность результата через существующий `useLatestPreview`.
Сброс предпросмотра не очищает формы или участки. Рисование, сохранение,
разрешение переходов и принятие результата остаются у своих сценариев.
Одновременно отмена увеличивает поколение запроса и запрещает позднему ответу
восстановить сброшенный результат. Дополнительного хранилища не создаётся.
