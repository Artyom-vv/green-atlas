# Отдельный сервер распознавания слоёв

Этот сервис не заменяет локальный API Green Atlas. Чертёж, XREF, геометрия,
проект и расчёт посадок остаются на компьютере пользователя. На VPS уходят
только данные каталога слоёв для двух операций: первый проход Luna и проверка
спорных слоёв. Сервер не принимает произвольные prompts, модель или инструменты.

## Размещение

Рабочий код берётся из проверенного commit `green-atlas-dev`; конкурсный
репозиторий не используется. Отдельная версия лежит в
`/opt/green-atlas-luna/releases/<version>`, отдельный venv в
`/opt/green-atlas-luna/venv`, служба `green-atlas-luna.service` слушает только
`127.0.0.1:8011`. Существующий API проектов на `127.0.0.1:8000` не меняется.

Nginx маршрутизирует только `POST /api/luna/recognize` к новой службе по
HTTPS. Путь требует bearer-токен, ограничен размером запроса и частотой.
Секрет OpenAI, SOCKS-прокси и персональный токен клиентов хранятся в трёх отдельных
файлах `/etc/green-atlas-luna/` с правами root-only. Systemd передаёт их
службе через `LoadCredential`. Не класть эти три секрета в release, Git, installer,
аргументы команд, журналы или переменные браузера.

Исходный SOCKS-прокси доступен с GetLuxe, но недоступен напрямую с VPS.
Отдельная служба `green-atlas-luna-egress.service` держит локальный порт
`127.0.0.1:11080` и пересылает его по SSH через GetLuxe к одному адресу
SOCKS-прокси. В `proxy.url` на VPS указан только этот локальный порт, а
учётные данные SOCKS остаются в том же root-only файле. Ключ SSH лежит в
`/etc/green-atlas-luna-tunnel`, доступен только служебной группе; ключ хоста
GetLuxe закреплён в отдельном `known_hosts`. На GetLuxe отдельный пользователь
`ga-egress` имеет ключ с запретом shell и разрешением пересылки только к
SOCKS-прокси. Доступ к общему API GetLuxe и его службы не изменяются.
Служба Luna запускается после туннеля. При его обрыве запрос к OpenAI не
переключается на прямое соединение.

Служба использует существующий `RecognitionBudget` с отдельным постоянным
журналом `/var/lib/green-atlas-luna/budget.sqlite3`; запуск запрещён, если
журнал отсутствует или повреждён. Инициализировать его один раз при первичной
установке. Изменять лимит можно только как отдельное продуктовое решение;
переустановка и смена версии не обнуляют расход.
Пустой или отсутствующий прокси также запрещает запуск: прямой выход к
OpenAI не является резервным маршрутом.

Клиент хранит **только** relay-токен в пользовательской папке AI или окружении.
На Mac настройка создаётся `scripts/configure-layer-relay.py --url
https://green-atlas.130-49-146-234.sslip.io/api/luna/recognize --token-file
<приватный-файл>`; значение токена в командную строку не передаётся. Для
Windows нужно обеспечить доступ к файлу только текущему пользователю.
Персональный relay-токен не упаковывается в дистрибутив.

## Отдельный доступ выпуска

По явному решению владельца выпуск Mac может содержать отдельные адрес relay
и токен выпуска, чтобы чистая установка работала без ввода ключей. Ключ OpenAI,
SOCKS-прокси и персональный relay-токен при этом остаются на сервере. Токен
выпуска извлекается из установщика, поэтому считается публичным доступом с
возможностью отзыва. Это не индивидуальная авторизация установки.

Сервер читает файл, указанный в `GREEN_ATLAS_RELAY_RELEASE_TOKEN_FILE`; в unit
задан `/etc/green-atlas-luna-release/release.token`. Формат: отдельный от персонального
токен из 32–512 видимых ASCII-символов без пробелов; допустим один завершающий
LF. Новый каталог должен быть `root:green-atlas-luna` с правами `0750`, файл
`root:green-atlas-luna` с правами `0440`. Персональный файл `0600` также
принимается, если его может читать процесс. Существующий root-only каталог
`/etc/green-atlas-luna` с персональными секретами не меняется. Запись для группы и любые права
для остальных пользователей запрещают доступ выпуска. Символическая ссылка,
каталог, pipe, отсутствие файла, ошибка чтения или неверный формат отключают
только этот доступ: персональный токен продолжает работать.

Файл читается на каждом `POST /recognize`, а не через снимок `LoadCredential`.
Для отзыва удалить файл; для смены атомарно заменить его заранее подготовленным
файлом с теми же владельцем и правами. Перезапуск не требуется. Не записывать
значение токена в команды или журналы. При включении этого механизма требуется
однократное обновление сервиса и его unit.

Оба доступа используют тот же provider, SOCKS-прокси, строгий формат пакета,
Nginx-ограничения размера и частоты и один существующий журнал
`/var/lib/green-atlas-luna/budget.sqlite3`. Общий накопительный лимит остаётся
`2_000_000` микро-USD, то есть $2. Отзыв, смена токена и установка нового выпуска
не меняют лимит и не обнуляют записи. При исчерпании бюджета AI недоступен для
обоих токенов; возврат расходов после ошибки также не добавляется.

Для публичного самообслуживания в дальнейшем понадобятся индивидуальные
учётные записи, выдача и отзыв токенов, а также серверные квоты.

## Приёмка

1. Проверить `systemctl is-active` обеих служб и `nginx -t`; прежний сайт,
   `/api/health`, проекты и скачивание выпуска должны работать без изменений.
2. Без bearer-токена новый путь возвращает 401, с неверным тоже 401.
   Неверный формат слоёв не делает запрос к OpenAI. Персональный токен и
   отдельный токен выпуска возвращают 422 на таком пакете; это позволяет
   проверить доступ без платного вызова.
3. С валидным токеном выполнить небольшой запрос на другой каталог слоёв,
   получить строгий JSON и проверить запись расходов в журнале.
4. Отключённый или неверный SOCKS-прокси не должен приводить к прямому
   запросу к OpenAI. Ошибка не содержит секретов.
5. На установленном Mac и Windows проверить новый DWG без пресета и точную
   Кустанайскую без ключа. Готовые предложения не становятся подтверждением.
   Для выпуска с доступом по умолчанию отдельно проверить чистый профиль без
   личных настроек и переменных OpenAI/relay. Windows проверяется своим выпуском,
   наличие Mac-комплекта не подтверждает готовность Windows.
6. Удалить или временно переименовать файл доступа выпуска: прежний токен
   выпуска получает 401, персональный по-прежнему 422 на неверном пакете.
   Вернуть файл атомарно и повторить проверку без перезапуска. Сравнить
   существующий журнал до и после: эти проверки не добавляют резервов.

Запрос `GET /v1/models` через туннель без ключа должен вернуть HTTP 401 —
это проверка маршрута без платного вызова. С ключом он должен вернуть HTTP 200;
`invalid_api_key` означает проблему ключа, а не туннеля. Платный smoke-тест
выполнять только после этой проверки, без автоматического повтора.
