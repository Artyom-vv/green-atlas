# AdminVPS: закрытая тестовая площадка

Адрес: https://green-atlas.130-49-146-234.sslip.io

Один VPS, 2 CPU / 4 ГБ / 60 ГБ, Ubuntu 24.04. Nginx отдаёт frontend и
проксирует `/api/` на единственный Uvicorn worker `127.0.0.1:8000`.
Вход для небольшой группы общий через HTTPS Basic Auth; это не персональные
аккаунты и не разграничение проектов. Всем участникам доступны общие проекты.
Агент отключён по указанию пользователя, модель на VPS не устанавливалась.

## Доступ и размещение

- SSH с этой машины: `ssh green-atlas-beta`.
- Приватный ключ находится в `C:/Users/New/.ssh/green_atlas_adminvps_ed25519`,
  вне репозитория; публичный ключ добавлен в `/root/.ssh/authorized_keys`.
- Пароль сайта хранится вне репозитория: `/root/green-atlas-access.json` на VPS,
  `C:/Users/New/.ssh/green-atlas-beta-access.json` на рабочей машине.
- Root-пароль не записывался в файлы проекта; существующий парольный доступ
  администратора не отключался.
- Приложение: `/opt/green-atlas/current` → каталог в `/opt/green-atlas/releases/`.
- Runtime: `/opt/green-atlas/venv`; версии зависимостей из `apps/api/uv.lock`.
- Настройки: `/etc/green-atlas/runtime.env`.
- База: `/var/lib/green-atlas/green-atlas.sqlite3`, вне каталога версии.
- Ежедневная согласованная SQLite-копия: `/var/lib/green-atlas/backups/`;
  хранится семь дней. Локальная копия на том же VPS не заменяет резервирование
  у провайдера. Пробное создание копии включает `PRAGMA integrity_check`.
- HTTPS: Let's Encrypt, `certbot.timer` и reload nginx после обновления.
  Бесплатное имя зависит от доступности DNS-сервиса sslip.io.

## Обновление

1. Собрать frontend с `VITE_API_URL` равным пустой строке (тот же origin).
2. Создать новый каталог версии с `api/app`, `api/pyproject.toml`, `api/uv.lock`,
   `web` (содержимое `apps/web/dist`) и `deploy` (этот каталог).
   В рабочей версии много незакоммиченных изменений: `git archive HEAD`
   не соответствует выложенному приложению. Не включать `.env`, ключи и базы.
3. Выполнить `bash <release>/deploy/bootstrap.sh <имя-версии>`.
   Скрипт синхронизирует зависимости по lockfile, переключает symlink и API.
   Это обновление с кратким перерывом, не атомарный blue-green deploy.
4. Для первой установки нужны `python3-venv`, `nginx`, `certbot`, `apache2-utils`;
   после bootstrap выполнить `enable-https.sh` и установить backup units.
5. Проверить HTTPS, проект и скачивание ZIP. Перед обновлением существующей
   площадки сделать SQLite backup. При изменении зависимостей откат требует
   повторного bootstrap предыдущей версии, а не только смены symlink.

## Приёмка

Выкладка 11 сентября 2026 года, `beta-20260911T092515Z`, включает текущие
незакоммиченные изменения поверх `9d42c214801f940e37a6c4fb0d7f99b95700392d`.
Frontend production build и diff-check прошли. На серверном Python 3.12
прошли **113 тестов** репозитория, конкуренции, памяти чата, ручного workflow
и roundtrip выпуска; в том числе реальные большие DXF. Время 242.54s,
одно deprecation-предупреждение Starlette/httpx. Это целевой прогон,
а не повтор полного набора backend-тестов.

Публичный HTTPS проверен с внешней рабочей машины: 401 без пароля, 200 после
входа, загрузка всех 69 статических файлов с совпадением хешей, создание проекта,
импорт DXF, расчёт геометрии, участок, посадка и ZIP с корректными CRC.
Пять одновременных чтений проекта прошли; пять параллельных тяжёлых импортов
этим не подтверждаются. Все 158 файлов source/backend и frontend совпали
с локальным срезом. После restart API полные project JSON и ZIP не изменились.
Проверены автозапуск API/nginx, таймер сертификата и успешная SQLite-копия.

Оставленный проект: `8907d080-d0d5-44f2-bb7f-5592f2d6b800`,
«Демо — проверка сервера 11 сентября». Локальные пользовательские проекты
не переносились. Отчёты: `public-verification.json`, `file-manifest.json`;
лог целевых тестов: `api-tests-final.log` в этом каталоге.

`verify-public.py` принимает путь к credentials JSON, DXF fixture и выходному
отчёту. Он намеренно создаёт помеченный демонстрационный проект, участок,
посадку и выпуск, оставляя их для проверки пользователя. Не запускать этот
скрипт как read-only мониторинг.

Проверки серверного Python 3.12 выполняются с отдельной тестовой базой через
`tests/conftest.py`. Добавлен deferred evaluation аннотаций в трёх модулях,
где метод `list` перекрывал одноимённый встроенный тип; локальный Python 3.14
ранее скрывал эту несовместимость. Предметная логика не менялась.

Встроенный браузер Codex не прошёл диалог HTTP Basic Auth; это ограничение
браузерной приёмки явно отделено от успешных HTTPS/API проверок. Открывать
площадку в обычном браузере и вводить логин/пароль в его окне авторизации.
