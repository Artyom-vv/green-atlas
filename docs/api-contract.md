# Публичный API

Этот файл описывает единственный поддерживаемый маршрут. Полная машиночитаемая
схема генерируется в `apps/api/openapi.json`; TypeScript-клиент в
`packages/api-client` создаётся только из неё.

## Проект и исходный DXF

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/api/projects` | создать пустой проект |
| `GET` | `/api/projects` | получить список сохранённых проектов |
| `GET` | `/api/projects/{id}` | получить проект без тяжёлой геометрии по умолчанию |
| `POST` | `/api/projects/{id}/source-dxf` | загрузить единственный исходный DXF |
| `GET` | `/api/projects/{id}/source-dxf/download` | скачать исходный DXF без преобразования |
| `PUT` | `/api/projects/{id}/layer-mappings` | подтвердить смысл слоёв для текущего среза правил |
| `DELETE` | `/api/projects/{id}` | удалить проект, исходник и план без восстановления |

DXF остаётся источником истины. API не принимает OSM, тепловые поверхности,
городские рейтинги или непроверенные справочные слои как замену чертежу.
Неудачная повторная загрузка не заменяет уже сохранённый DXF, ручную схему или
доступные результаты экспорта.

Если подготовка карты остановилась на битой или неподдерживаемой геометрии,
оператор может скачать исходник в точности в том виде, в котором загрузил его.
Этот путь не запускает расчёт, не строит карту и не изменяет проект; в
интерфейсе он появляется только как действие восстановления при ошибке.

Для текстовых DXF чтение учитывает `$ACADVER` и `$DWGCODEPAGE`: ранние
версии читаются в объявленной кодовой странице, DXF R2007 и новее — в UTF-8.
При экспорте исходная кодировка сохраняется вместе с геометрией; например,
CP1252-файл не интерпретируется как CP1251 только из-за русского fallback.

## Карта и выбранные области

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/api/projects/{id}/operations/geometry` | запустить подготовку геометрии в фоне |
| `GET` | `/api/projects/{id}/operations/latest` | узнать состояние подготовки карты |
| `GET` | `/api/projects/{id}/operations/{operation_id}` | получить прогресс операции |
| `POST` | `/api/projects/{id}/operations/{operation_id}/cancel` | остановить операцию |
| `GET` | `/api/projects/{id}/map-features` | получить фрагмент геометрии по viewport |
| `PUT` | `/api/projects/{id}/planting-zones` | сохранить один или несколько выбранных полигонов |

Позиция вне выбранных областей блокируется. Нетипизированная коммуникация не
становится выдуманным буфером: при пересечении она возвращает статус
`unknown`, требует уточнения, но остаётся видимой на карте.
Самопересекающийся контур, сопоставленный как граница, здание или дорога,
останавливает расчёт с перечислением слоёв: сервис не исправляет такой
контур автоматически и не изобретает его фактическую площадь.
CAD-сущность без проверяемой 2D-проекции (`3DSOLID`, `REGION`, mesh или
неизвестный proxy-объект) также останавливает расчёт, если её слой назначен
физическим ограничением. Иначе занятая территория могла бы выглядеть
свободной. Исходник при этом остаётся доступен для скачивания.
Та же защита действует, если карта вместила только часть плотного слоя или
одна CAD-кривая превышает лимит детализации. Такой слой явно помечается как
неполный; пока он назначен границей, зданием, дорогой, сетью или существующим
озеленением, подготовка карты не запускается. Оператор выбирает меньший
рабочий фрагмент либо сознательно исключает слой из расчёта.
Тот же принцип действует для нарисованной рабочей области: некорректный
контур отклоняется, а уже сохранённые области не заменяются. Объекты DXF с
`NaN` или бесконечными координатами не передаются в карту и расчёт, но
сохраняются в исходном файле для исправления и повторной загрузки.

Если в DXF нет внешней границы территории, операция подготовки карты всё
равно завершается: она показывает подтверждённые препятствия, но не рисует
фиктивную общую «разрешённую зону». Оператор обводит рабочую область сам; она
становится границей ручной схемы и проверяется при каждом размещении. Поле
`map_ready` в проекте позволяет клиенту отличить такую подготовленную карту
от обычного просмотра ещё не обработанного исходника.

## Схема и наборы изменений

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/api/projects/{id}/plan/manual` | открыть пустую ручную схему после выбора областей |
| `POST` | `/api/projects/{id}/plan/placement-check` | проверить позицию до установки объекта |
| `POST` | `/api/projects/{id}/plan/change-sets/preview` | рассчитать атомарный набор изменений без сохранения |
| `POST` | `/api/projects/{id}/plan/change-sets/apply` | применить подтверждённый набор одной версией плана |
| `POST` | `/api/projects/{id}/plan/objects` | добавить дерево или кустарник |
| `PATCH` | `/api/projects/{id}/plan/objects/{object_id}` | переместить или изменить объект |
| `POST` | `/api/projects/{id}/plan/objects/delete` | удалить выбранную группу |
| `GET` | `/api/projects/{id}/plan/history` | получить состояние undo/redo |
| `POST` | `/api/projects/{id}/plan/history/undo` | отменить последнее изменение |
| `POST` | `/api/projects/{id}/plan/history/redo` | повторить отменённое изменение |

`PlanObject` теперь явно отделяет монтажный радиус `layout_radius_m` от
будущих прогнозов кроны и корней. Старое поле `radius` временно сохраняется
для совместимости и DXF-экспорта, но не означает взрослую крону. Посадочное
место также может хранить размерный класс, ревизию вида, группы, рисунок и
признак закрепления; неизвестные биологические данные остаются пустыми.

Preview возвращает результат по каждой операции, стабильные ID будущих
объектов и digest. Он не меняет проект. Apply повторно сверяет digest и
`base_plan_version`; если хотя бы одна операция заблокирована, не сохраняется
ничего. Несколько добавлений, перемещений и удалений создают одну версию плана
и одну запись undo. Старые одиночные маршруты временно являются адаптерами
того же change-set ядра.

Проверка не является отдельным шагом или действием, которое может быть
забыто. Она запускается при добавлении, перемещении и удалении посадки;
результат остаётся в текущей схеме и открывается в панели замечаний.

## Экспорт и ошибки

`POST /api/projects/{id}/exports` создаёт и сохраняет DXF из исходного файла и
отдельных слоёв `GREEN_ATLAS_TREES` и `GREEN_ATLAS_SHRUBS`. Если во входном
DXF уже есть такой слой, экспорт создаёт следующий свободный суффикс и не
смешивает посадки с исходной геометрией. `GET
/api/projects/{id}/exports/{artifact_id}/download` всегда возвращает именно
этот артефакт, даже если текущая схема изменилась или сервис был перезапущен.
Версия проекта и байты артефакта фиксируются одной атомарной операцией: при
конфликте одновременных изменений не публикуется недоступный файл. Экспорт
не меняет стадию ручной схемы: это снимок текущего состояния, а не переход в
отдельный режим.

Все прикладные ошибки используют одну форму:

```json
{
  "code": "string",
  "message": "string",
  "field_errors": {},
  "details": {}
}
```

Изменяющий запрос несёт `If-Match` с `state_version`. При одновременной
работе API возвращает `409 PROJECT_VERSION_CONFLICT`; клиент обязан перечитать
проект, а не применять изменение поверх другого состояния.
Устаревший preview отдельно возвращает `409 PLAN_VERSION_CONFLICT`.
