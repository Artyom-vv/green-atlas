# Правила модулей

## CAD: обязательная граница развития

См. [AutoCAD-контракт](architecture/autocad-contract.md) и
[локальные проверки зависимостей](../scripts/architecture/README.md).
Native capture не импортирует legacy reader; расчёт не читает CAD-файлы;
архив для выпуска не становится вторым входом расчётной геометрии.
Новые связи с legacy reader/conversion/AOI запрещены ratchet-тестом.
Существующие исключения — долг миграции, не целевой граф. Нельзя расширять
baseline без отдельного решения. Выбор алгоритма не подменяется рефакторингом.

## Backend

- Domain-контракты не импортируют FastAPI, хранилища и конкретные библиотеки геометрии.
- Application-сценарии зависят только от моделей и портов.
- Adapters реализуют порты и могут быть заменены без изменения HTTP API.
- API создаёт composition root и переводит исключения в публичный `ApiError`.
- Межмодульное изменение агрегата выполняется через `ProjectApplication`, не прямым вызовом чужого adapter.

Детерминированные адаптеры обязаны выдавать воспроизводимый результат. Случайность допустима только после явного seed, зафиксированного в проекте и тесте. Реальные DXF- и геометрические адаптеры проверяются round-trip и контрактными тестами.

Публичные объяснения принадлежат общему каталогу сообщений, причины отказов —
типизированному контракту. Технические порции и параметры сценария принадлежат
его конфигурации; нормативные расстояния — реестру правил. Значения по умолчанию
из API-контракта не дублируются в клиенте без отдельной продуктовой причины.
Комментарии и описания собственного изменяемого кода пишутся по-русски: они
объясняют доменную обязанность, ограничение или причину решения, а не повторяют
название метода. Идентификаторы протоколов и библиотек сохраняют исходную запись.

## Frontend

Разрешённое направление:

```text
app → pages → widgets → features → entities → shared
                             ↓          ↓
                        @green/api-client
shared/ui → @green/ui
```

- `@green/ui` не содержит DXF-, картографической или озеленительной терминологии.
- Новый код не импортирует legacy `domain-ui`; текущие границы проверяет ESLint.
- Pages и widgets координируют сценарии через features; UI не вызывает API напрямую.
- Серверные данные принадлежат TanStack Query, формы — своим контроллерам,
  состояние редактора — существующему владельцу. Вычисляемые признаки выводятся
  из явных состояний. Native-адаптер передаёт запрос перехода, а решение о
  сохранности работы принимает общий сценарий интерфейса.
- Все потребители кеша сохранённого проекта используют единые query options
  из `entities/project/api`. Чтение проверяет нижнюю границу подтверждённых
  версий; дополнительный observer не подменяет этот контракт своим queryFn.
- OpenLayers используется только внутри `MapViewport`.
- Сгенерированный API-клиент не редактируется вручную.

## Подкаталоги и размер координаторов

Подкаталог объединяет обязанности сценария: захват, подготовку, измерения,
поиск, проверку, представление или применение. `domain`, `model` и `ui` остаются
архитектурными ролями; десятки несвязанных обязанностей не складываются в один
плоский список. Пустой Python `__init__.py` нужен для discovery пакета и сборки,
а не для реэкспорта реализации.

Большой координатор передаёт самостоятельную обязанность её владельцу. Не
создавайте общий Context с формами, запросами, renderer и десятками callbacks.
Порты содержат только входы своей обязанности. Перенос строк в новый файл не
считается сокращением: отдельно измеряются удалённые повторы и оставшиеся
ответственности. Переезд сохраняет граф зависимостей и обновляет все потребители,
worker-команды, quality scopes и сборку в одной контрольной точке.


## Поддерживаемость и готовые решения

Качество определяется границей ответственности и ценой изменения. Количество
строк — справочный размер, отдельно от сложности, повторов и собственного
бойлерплейта. Делегирование библиотеке может увеличить явные декларации,
одновременно убрав ответственность за протокол или генерацию запросов.

Каждый собственный модуль API начинается с русского описания домена, задачи
и существенной границы. Публичные входы расположены перед внутренними
помощниками; `_` означает локальную реализацию, которую другой модуль не
импортирует как неявный контракт. Реально переиспользуемая обязанность
получает явный публичный вход; остальные методы остаются внутренними.

Отдельная функция объединяет именуемую обязанность и её инварианты, а не
каждое тело цикла. Части, меняющиеся по одной причине, остаются вместе.
Новый файл нужен самостоятельному владельцу, не очередному фрагменту метода.
Нельзя маскировать зависимости большим Context, произвольным `Any` или
универсальным реестром сценариев. Типы отражают действительный вход и результат;
`Any` допускается на расширяемой библиотечной границе, а не вместо доменной модели.

Для SQL/DDL используется SQLAlchemy Core на существующем SQLite-соединении.
Транзакция, конфликт версии и подтверждение изменения принадлежат сценарию
сохранения; компилятор SQL не создаёт соединение, не делает commit и не
перехватывает доменные ошибки. Для DTO и данных конфигурации используется
Pydantic; для JSON, CSV и ZIP — готовые стандартные библиотеки.

Декоратор допустим для повторяемой границы: перевод ошибок, метаданные
маршрута или время жизни ресурса. Он сохраняет сигнатуру и sync/async поведение
готовыми средствами библиотеки. Последовательность записи, отмены, проверки
источника и публикации результата остаётся видимой в сценарии. Стандартный
`contextlib.contextmanager` поддерживается Python и не заменяется самописным
классом ради предупреждения редактора.

Основания: [разделение ответственности Robert C. Martin](https://blog.cleancoder.com/uncle-bob/2014/05/08/SingleReponsibilityPrinciple.html),
[выделение функции Martin Fowler](https://refactoring.com/catalog/extractFunction.html),
[проектирование абстракций John Ousterhout](https://web.stanford.edu/~ouster/CS349W/lectures/abstraction.html),
[контекстные менеджеры Python](https://docs.python.org/3/library/contextlib.html).

## Готовность нового модуля

Новый модуль принимается, когда у него есть публичный сценарий, порт, детерминированный adapter или реальная реализация, unit-тест контракта порта, единообразная ошибка и отсутствие запрещённых импортов.
