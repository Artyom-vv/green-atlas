# Качество и показатели

## Что проверяется

| Уровень | Предмет проверки | Критерий |
|---|---|---|
| Передача | Версия, размер и контрольная сумма | Принят целый пакет одного источника |
| Геометрия | Области, отверстия, линии и погрешность | Нет скрытой подмены либо потери представления |
| Полнота | Доступные, восстановленные и пропущенные объекты | Каждый статус имеет конкретное основание |
| Размещение | Препятствия, граница и соседство | Одинаковые правила для ручного и автоматического ввода |
| Сохранение | Ревизия и состав изменений | Устаревший вариант не применяется молча |
| Повторное открытие | Количество, координаты и участки | Сохранённый план воспроизводится |
| Дистрибутив | Ресурсы и запуск | Работа без файлов исходного checkout |

Число элементов карты нельзя сравнивать напрямую с числом исходных
CAD-объектов. Отсутствие ошибок не доказывает полноты исходника.

## Контрольный сценарий

1. Создать проект из отдельной копии исходника.
2. Проверить XREF, назначения и расчётную границу.
3. Подготовить карту и рассмотреть адресные замечания.
4. Проверить заведомо запрещённые точки внутри здания и проезда.
5. Выполнить ручное и автоматическое размещение.
6. Сохранить вариант и повторно открыть проект.
7. Сверить количество и координаты посадок.
8. Отдельно проверить закрытие и новый запуск приложения.

Возврат к проекту через список не равен холодному запуску.
Выпуск CAD-файла имеет собственную приёмку.

## Быстрый маршрут проверки стабилизации

Перед запуском выбирается конкретный сценарий, его ожидаемый результат и
профиль. Продолжение проекта, ошибки и сохранение проверяются на небольших
изолированных базах с готовой геометрией. Новый импорт через Core выполняется
отдельно при изменении границы CAD или перед выпуском установленного комплекта.
Большая рабочая база не копируется для каждой проверки интерфейса.

| Сценарий | Ожидаемый результат | Готовая проверка |
|---|---|---|
| Подтверждённые слои и граница, снимка ещё нет | Одно действие готовит карту и открывает рабочую область | `SetupPage.test.tsx`, `usePreparationCompletion.test.tsx` |
| Ошибка, отмена или потеря потока прогресса | Видимое конечное состояние либо восстановление наблюдения; новая запись не запускается | `usePreparationOperationObservation.test.tsx`, `test_operation_events.py`, `test_operations.py` |
| Ответ применения потерян или чтение после записи не удалось | Квитанция подтверждает запись; повторного применения нет | `usePlanChangeCommit.test.tsx`, `test_change_receipts.py`, `test_project_mutation_receipts.py` |
| Устаревшая версия проекта | Адресный конфликт; исходная версия сохраняется | `test_planting_zone_changes.py`, `test_planning_horizon.py` |
| Закрытый AutoCAD и повторное чтение | План, координаты, основания и история сохраняются | `test_prepared_geometry.py`, `test_local_project_api.py`, `test_planning_horizon.py` |
| Повтор ticket, прерывание передачи или поздний ответ | Один проект, явное возобновление, отбрасывание чужого ответа | `test_desktop_handoff.py`, native self-tests |
| Распознавание без внешней модели | Локальные правила завершаются; неясные назначения сохраняют свою причину | `test_layer_recognition_local_first.py`, `SetupPage.recognition.test.tsx` |

Веб и native выполняются из корня checkout на Mac:

```sh
mkdir -p output/stability-fast
pnpm test:stability:web --reporter=default --reporter=junit --outputFile.junit=../../output/stability-fast/web.xml
pnpm test:stability:native
```

API выполняется из каталога `apps/api`:

```sh
.venv/bin/pytest -c pytest-stability.ini --junitxml=../../output/stability-fast/api.xml > ../../output/stability-fast/api.log 2>&1
```

Рабочий каталог API обязателен: pytest иначе выбирает весь checkout вместо
списка `testpaths` из профиля. Исполнитель передаёт каталог запуска явно.

Первый профиль использует зафиксированную dev-зависимость `pytest-timeout`.
При установке окружения применяется `uv sync --project apps/api --locked --group dev`.
На Windows перед каждой командой выполняется `windows-env.ps1`; Python берётся
из `.venv/Scripts`, native-профиль выше предназначен для Mac.

API и веб прекращают профиль при первой ошибке. Отдельный тест ограничен
пятью секундами. Для API выбран режим `thread`: при зависании тестовый процесс
завершается со стеками в stderr. Поэтому сохраняется также сырой журнал запуска;
JUnit используется для завершившихся прогонов. Запуск API направляет stdout
и stderr в `output/stability-fast/api.log`, чтобы жёсткое завершение сохраняло
диагностику. Используются готовые механизмы pytest-timeout и Vitest;
первоисточники: [[06 Исследования и решения/Источники и решения]].

Измерение 9 октября: 73 проверки локального продолжения заняли 2,78 секунды;
расширенный API-профиль из 188 проверок — 17,13 секунды; веб-профиль из
164 проверок — 6,41 секунды. Шесть native-проверок с компиляцией заняли
11,82 секунды. Изолированный запуск установленного runtime 0.1.65 занял
20,86 секунды и скопировал только 65,6 МБ runtime. Копирование всей базы
для frozen-проверки сохранения включается отдельно с объявленной маленькой
фикстурой.

Для уже запущенного приложения используется ограниченная проверка HTTP:

```sh
env PYTHONPATH=apps/api apps/api/.venv/bin/python tools/autocad-bridge/diagnostics/check_live_http.py --status --recognition --url "$GA_STATUS_PROJECT_URL" --receipt output/stability-fast/live-status.json
```

URL содержит локальный порт приложения и путь `/api/projects/{id}`. Проверка
читает здоровье API, последнюю подготовку и распознавание: максимум три GET
и пять секунд на весь запуск. Для защищённого API сессия передаётся явно
через `--session-stdin`; без неё отказ авторизации завершается сразу.
Команда не запускает импорт, распознавание или расчёт и не читает секреты
из профиля. Ошибка, разрыв соединения и таймаут возвращают код 1 с причиной.

Проверка 69 сохранённых посадок на подготовленном снимке заняла 2,81 секунды.
После добавления ещё 90 повторная проверка всех 159 позиций заняла 3,24 секунды:
центры находятся в слоях, подтверждённых в проекте как газоны; попаданий
в известные площади зданий, дорог и технических зон нет. Это проверка
подготовленной геометрии и текущих назначений, без экспертного эталона
классификации. Отдельная точка предпросмотра без координат не подменяется
этим результатом. SHA снимка и основания проекта проверяются перед измерением;
проект и его история не изменяются.

После автоматических проверок UI проверяется по заранее выбранным кадрам:
прогресс, конечная ошибка и готовая карта. Произвольные клики по чертежу
не используются как тестовые данные: расчётная зона задаётся контрольной
фикстурой и сверяется с геометрией. Автоматические фикстуры проверяют контракт
сценария; реальный DWG и установленный пакет имеют отдельную приёмку.

## Измерение производительности

Отдельно измеряются чтение снимка, построение области поиска, подбор,
проверка, сохранение и отображение. Для результата фиксируются исходник,
версия программы, параметры растения и состояние кеша.

Время одного этапа нельзя выдавать за полное время работы интерфейса.

## Поддерживаемость кода

Количество строк описывает размер, но не качество. Принимаем изменение по
явным владельцам, удалённому повторению и ответственности, переданной готовому
решению. Декларации SQLAlchemy могут увеличить файл, одновременно упростив
изменение таблицы или запроса. Разделение метода полезно, когда название входа
объясняет самостоятельную обязанность и её инварианты.

| Обязанность | Готовый механизм | Что остаётся у Green Atlas |
|---|---|---|
| Схема и построение SQL | SQLAlchemy Core | Транзакция, CAS, история и квитанция на прежнем соединении |
| DTO и конфигурация | Pydantic и TypeAdapter | Значение свидетельства и применимость правила |
| Синтаксис JSON, CSV, ZIP | Стандартные библиотеки Python | Состав выпуска, источник, контрольные суммы и версии |
| Граница ошибок HTTP | FastAPI APIRoute и functools.wraps | Типизированная причина отказа и её публичное объяснение |
| Измерения геометрии | Shapely и подготовленный снимок | Подтверждённая точность, полнота и нормативный отступ |

Для паспорта, шаблонов посадок и выпуска контрольные результаты закреплены
до изменения: сравнивается полный ответ и порядок, а для выпуска — байты
артефактов. Для SQL сравниваются типы, колонки, ключи, индексы, PRAGMA и
поведение конфликтов и отката. Общее число успешных тестов не заменяет эти
адресные проверки.

Делегирование не означает ускорения. Локальный профиль показал дополнительную
стоимость компиляции SQL порядка 0,1 мс на короткий запрос и сериализацию
тестового manifest с 10 тысячами элементов за 168 мс вместо 34 мс. Байты
совпали; память изменилась с 1,86 до 1,94 МБ. Это цена библиотечной границы,
а не основание заявлять выигрыш производительности всего сервиса.

### Следующие границы упрощения

Порядок определяется связностью обязанностей и риском изменения, не размером.

| Участок | Почему требует внимания | Граница следующей работы |
|---|---|---|
| Примитивы активного компилятора CAD | Нормализация пути повторно сериализует его; часть геометрических диагностик остаётся в функциях | Использовать одну подписанную проекцию примитива без второго графа координат |
| `ImportApplication.save_mappings` | Назначения меняют исходную модель, основания и производные данные | Выделить чистую политику изменения оснований; запись остаётся одной операцией |
| `ChangeSetApplication.preview_on_snapshot` и проверка плана | Разные команды повторяют работу с кандидатами и объяснениями | Использовать типизированные операции и общий оценщик без универсального workflow |
| Модель workspace и взаимодействия карты | Координаторы объединяют состояние, сцены и обработку событий | Разделить реальные владельцы жизненного цикла; сохранить Query, формы и текущую библиотеку карты |

Legacy-парсер и прежние форматы сохраняют свою границу совместимости.
Развитие нового импорта туда не переносится. Порт Windows проверяется отдельным
этапом на Windows; успешный прогон Mac его не подтверждает.

Прежний кандидат `_read_snapshot` проверен по графу вызовов: он не является
владельцем действующего приёма, а его worker исключён из разрешённых запусков.
Рефакторинг нового входа проведён в `cad_bridge/compiler.py`; старый worker
не переписан ради размера файла.

## Зафиксированные результаты

### Допуск XREF и политика производителя, 8 октября 2026

Скалярная форма свидетельств XREF передана Pydantic. Физическая проверка
файла отделена от обхода реестра; возможности производителя и технические
диагностики имеют свои типизированные владельцы. Нового парсера, общего
workflow или второго графа координат нет. Успешные снимки сохраняют все
поля, порядок записей и хеши. Повреждённый статус ссылки даёт отказ допуска
вместо случайного TypeError; список принимаемых версий не расширен.

Сравнены 1800 случаев до и после: все 939 принятых снимков и их хешей
совпали полностью. Двенадцать отличий относятся только к отказам на статусе
в виде списка или объекта. Дополнительные 16 словарных входов проверили
бинарные значения: новых допусков нет; два отказа bytearray также стали
предметными. Входные словари не изменяются. Политики пяти возможностей
и порядок прежних отказов совпадают с контрольной точкой.

На синтетическом захвате с 10 тысячами независимых областей полные снимки
и пики выделенной памяти совпали для чтения байтов и файла. Это проверка
границы памяти и сохранности результата, а не замер реального DWG или всего UI.

Регрессия: 2063 успешных API-теста, три прежних xfail. Mypy проверил 293
настроенных файла; Ruff и форматирование прошли для 378. OpenAPI и SDK
не изменились; новых legacy-зависимостей нет. Проверки документации и
архитектурных инструментов прошли.

Итоговый автономный runtime собран для Mac 14 на Python 3.14.3.
Девять проверок ресурсов, запуска и границы дочерних процессов прошли;
отдельный сценарий автоматической посадки пропущен без подготовленной
тестовой базы и идентификатора проекта. Рабочее приложение не обновлялось,
пользовательские чертежи и базы не менялись. Windows в этом срезе не запускался.

### Упрощение обязанностей API, 8 октября 2026

Схема и построение SQL переданы SQLAlchemy Core на прежних соединениях.
Паспорт, выпуск и предпросмотр шаблонов получили отдельные типизированные
обязанности; синтаксис manifest передан стандартному JSONEncoder.
Публичные тексты этих сценариев, параметры SQLite и сведения нормативных
документов имеют проверяемые справочники. Расстояния и хеш правил сохранены.

Полная регрессия: 1988 успешных API-тестов и три прежних ожидаемых xfail;
1238 тестов web, UI и API-client. Шесть browser-сценариев проверили паспорт,
адресный пропуск CAD-объекта и видимость завершения операций. Полные ответы
десяти паспортов и 22 шаблонов, байты 18 артефактов выпуска совпали с исходными.
Структура десяти таблиц и настройки SQLite сохранены. OpenAPI отличается
только двумя русскими описаниями моделей; поля, типы и defaults совпадают.

Ruff и форматирование прошли; mypy проверил 291 настроенный файл и отдельно
37 изменённых файлов. У всех 338 API-модулей есть русские вводные описания.
Перевод внутренних комментариев и функций отдельно сверён по исполняемому
AST, директивам и сохранности описаний классов и маршрутов.

Автономный runtime собран из итогового кода на Python 3.14.3 для Mac 14:
восемь проверок ресурсов и запуска прошли. Холодное восстановление с реальным
CAD-ticket в этом срезе пропущено, так как отдельный ticket не предоставлялся.
Установленное приложение этим исходным срезом не обновлялось.

### Видимость длительных операций и качество кода, 7 октября 2026

Mac 0.1.58 разделяет квитанцию завершения и чтение результата. Проверены
медленное и ошибочное завершающее чтение, устаревший кеш готовности, поздний
отменённый ответ и возврат к просмотру исходника. Распознавание видно над
закрытыми разделами и с карты. Выпуск сохраняет отдельную индикацию после
закрытия окна; одновременно план может корректно показывать «Изменения
сохранены». Повторные действия чтения не отправляют запись заново.

Общий прогон: 2873 успешных API-теста, один skip и три ожидаемых xfail;
1485 тестов web, UI и API-client. Пять browser-сценариев проверяют реальный
интерфейс при управляемых HTTP-ответах. TypeScript, ESLint, форматирование,
BEM, OpenAPI, настроенные Ruff/mypy и CAD-ratchet прошли. Mypy охватил 241
явно включённый файл вместе с тестами; это не проверка типов всего API.

Аудит проиндексировал 1620 исходных файлов Mac и отдельно сравнил Windows;
54 файла рассмотрены вручную по обязанностям. Выделены восемь ограниченных
задач: расширить проверяемую область Python, разделить нормализацию native
входа, выделить жизненный цикл сцены из workspace, отделить взаимодействия
карты и picking, именовать технические бюджеты поиска, свести повторяемую
типографику к теме, убрать дублирование native source lists и согласовать
общее ядро перед Windows-переносом. Размер файла сам по себе не считался
доказательством ошибки; нормативные числа не заменялись техническими лимитами.

В этом срезе выделены узкие обязанности чтения, завершения подготовки и
наблюдения за распознаванием. Используются существующие Query, RHF, Pydantic
и UI-компоненты; нового общего workflow-движка или CAD-парсера не добавлено.

### Локальные свежие проекты, 5 октября 2026

Mac 0.1.54 установлен с плагином и worker 0.1.47. Хеш рабочей базы до и после
обновления совпал; обычный запуск из `~/Applications` открыл библиотеку.
В отдельном свежем профиле интерфейс сохранил сведения проверяющего и новую
посадку, затем прошёл штатный выход и холодное открытие. План, координаты,
история, основания и подтверждения записи совпали по всем 19 сравнениям.
Подготовленная геометрия не изменилась при смене проверяющего; расчёты и
сохранение в этом прогоне не обращались к CAD или внешней модели.

Исправления двух обнаруженных состояний интерфейса включены в подготовленный
комплект 0.1.55. Проверены 1301 web-тест в 220 файлах, типизация, lint, BEM
и совпадение OpenAPI. Тест общей защиты воспроизводит старую гонку навигации
без исправления и проходит с ним. Форматирование пяти затронутых файлов
прошло; общая проверка сообщает замечания в 69 неизменённых файлах исходной
версии. Они не переформатированы, исключения не добавлены. Установка и
проверка изменённого интерфейса 0.1.55 ожидают доступа к окну Mac.
