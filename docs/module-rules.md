# Правила модулей

## CAD: обязательная граница развития

См. [AutoCAD-контракт](architecture/autocad-contract.md) и
[локальные проверки зависимостей](../scripts/architecture/README.md).
Native capture не импортирует legacy reader; расчёт не читает CAD-файлы;
архив для выпуска не становится вторым входом расчётной геометрии.
Новые связи с legacy reader/conversion/AOI запрещены ratchet-тестом.
Существующие исключения — долг миграции, не целевой граф. Нельзя расширять
baseline без отдельного решения. Выбор алгоритма не подменяется рефакторингом.

## Backend

- Domain-контракты не импортируют FastAPI, хранилища и конкретные библиотеки геометрии.
- Application-сценарии зависят только от моделей и портов.
- Adapters реализуют порты и могут быть заменены без изменения HTTP API.
- API создаёт composition root и переводит исключения в публичный `ApiError`.
- Межмодульное изменение агрегата выполняется через `ProjectApplication`, не прямым вызовом чужого adapter.

Детерминированные адаптеры обязаны выдавать воспроизводимый результат. Случайность допустима только после явного seed, зафиксированного в проекте и тесте. Реальные DXF- и геометрические адаптеры проверяются round-trip и контрактными тестами.

## Frontend

Разрешённое направление:

```text
app/pages → features → domain-ui → @green/ui
                         ↓
                  @green/api-client
```

- `@green/ui` не содержит DXF-, картографической или озеленительной терминологии.
- `domain-ui` не вызывает API и не рассчитывает нормативы.
- Pages координируют TanStack Query, формы и переходы.
- OpenLayers используется только внутри `MapViewport`.
- Сгенерированный API-клиент не редактируется вручную.

## Готовность нового модуля

Новый модуль принимается, когда у него есть публичный сценарий, порт, детерминированный adapter или реальная реализация, unit-тест контракта порта, единообразная ошибка и отсутствие запрещённых импортов.
