# Текущее состояние

Геометрический production-маршрут теперь начинается в AutoCAD: native extraction → immutable evidence и coverage → admission. После него ещё отдельно требуются пользовательская классификация слоёв и расчёт ограничений. Сквозная пользовательская приёмка «AutoCAD → семантика → расчёт → выпуск» пока не доказана.

## Реализовано

- модульный FastAPI backend и React workspace;
- read-only native extraction корневого DWG/DXF и детерминированных package-local XREF;
- protocol `0.1.33` и изолированная очередь `v033`;
- immutable evidence, SHA-256 зависимостей, coverage и snapshot admission;
- фоновая подготовка геометрии и выдача данных по viewport;
- ручные области посадок;
- одиночные, групповые и шаблонные изменения с preview/apply;
- undo/redo в SQLite;
- каталог пород и горизонты роста;
- проверка плана и выпуск артефактов;
- проверенный реальный native-прогон Кустанайской улицы: 101829 source, 79625 calculation, 22197 context, 7 unresolved instances; admission и topology verifier прошли;
- установленная Mac-сборка для следующего запуска; текущая пользовательская AutoCAD-сессия не сохранялась и не закрывалась.

## Активная граница разработки

Реализовано, но не подтверждено end-to-end: desktop delivery/pairing, пользовательская сверка semantic layer mappings, расчёт ограничений из нового snapshot и выпуск из этого пользовательского маршрута. План: матрица улиц, Windows, Developer ID/notarization и завершённая пользовательская команда. Исторические DXF-конвертации и ручные MCP-обходы не являются каноническим production-flow.

## Состояние источников

Рабочее дерево содержит незакоммиченные изменения. Поэтому эта документация описывает текущий checkout, а не только commit `0f23875`. Перед публикацией нужен повторный аудит после стабилизации ветки.
