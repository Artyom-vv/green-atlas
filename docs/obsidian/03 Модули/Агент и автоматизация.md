# Агент и автоматизация

## Назначение

Подготавливать предложения по проекту через обычные сценарии приложения.
Агент не является CAD-парсером и не заменяет модуль геометрической проверки.

## Вход и результат

Вход: запрос пользователя, доступное состояние проекта и набор разрешённых
инструментов. Подключение внешней модели определяется конфигурацией среды.

Результат: ответ, предлагаемое действие либо предпросмотр изменений.
Наличие runtime и записей выполнения не означает, что внешний провайдер
модели настроен и проверен в конкретной сборке.

## Порядок работы

1. Получить задачу и доступные данные проекта.
2. Сформировать предложение с помощью подключённого интерпретатора.
3. Выполнить разрешённые запросы через общие сценарии приложения.
4. Показать результат или предпросмотр.
5. Применить изменение только через обычный механизм подтверждения.

## Граница ответственности

| Агент может | Агент не подтверждает |
|---|---|
| Предложить назначение по доступным признакам | Истинный смысл неоднозначного слоя |
| Подготовить запрос подбора | Геометрию отсутствующего объекта |
| Объяснить результат проверки | Неизвестную глубину и параметры сети |
| Сформировать предпросмотр | Нормативное согласование проекта |

Предложение модели проходит ту же проверку данных и геометрии,
что и действие пользователя. Отдельного обхода ревизий и ограничений нет.

## Зависимости и ограничения

Модуль зависит от сценариев проекта, планирования, проверки и хранения.
Основной маршрут проектировщика доступен без агента.

При распознавании CAD-слоёв в OpenAI передаются только метаданные слоёв:
имена, количество и типы объектов, цвет, тип линии, полнота геометрии и
признаки контура. Для каждой группы слоёв модель видит также каталог имён
всего исходника. Сам чертёж и его координаты не отправляются. Категории с
однозначной расчётной ролью применяются автоматически; границу территории
пользователь выбирает отдельно. Для неоднозначных категорий модель может
предложить расчётную роль одной кнопкой, но не подтверждает её сама.
Если пользователь выбрал границу или поправил слой во время распознавания,
готовые предложения применяются к остальным слоям в текущей форме без потери
ручного выбора. Сохранение такого смешанного решения происходит при подготовке
карты; чистый неизменённый набор сохраняется автоматически.
Второй запрос анализирует только спорные предложения первого и сокращает
ручной выбор до нескольких ролей или одного вопроса. В нём дополнительно
указываются доступные типы геометрии, число непрочитанных объектов и размеры
охвата слоя без исходных координат. Повторная модельная
уверенность не отменяет проверки состава объектов перед исключением слоя.
Сведения о глубине, способе прокладки и нормативных отступах модель не
выводит из имени сети. При недоступном API сохраняется классификация по
названиям; ранее упакованные предложения для точного исходника доступны
без ключа, если контрольные суммы совпадают.

Ручное получение предложений во внешнем инструменте не является встроенной
интеграцией приложения. При недоступности модели нельзя представлять
статическое предложение как выполненный внешний запрос.
