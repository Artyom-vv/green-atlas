# Веб интерфейс и 3D

## Назначение

Провести пользователя через импорт, подготовку, проектирование, проверку и выпуск в одном пространстве карты.

## Архитектура

Страницы координируют маршрут и запросы. Features реализуют действия, entities — предметные состояния, widgets — крупные области экрана. `@green/ui` остаётся независимым от CAD и озеленения. Типы API генерируются из OpenAPI.

## Карта

Один экземпляр `MapViewport` сохраняется при переключении панелей. Геометрия запрашивается по viewport с буфером. Исходные объекты, план, preview и selection overlay разделены, чтобы временное состояние не смешивалось с сохранённым.

## 3D

Three.js используется для отдельного пространственного просмотра плана и горизонтов роста. 3D является производным представлением, а не источником проектной геометрии.

## Ограничения

- браузер не рассчитывает нормативы самостоятельно;
- 3D не компенсирует отсутствующие данные высот или поверхности;
- поддержка больших файлов зависит от бюджетов viewport и детализации;
- доступность и производительность требуют повторной приёмки на целевых устройствах.

**Проверено:** компоненты и API-контракты покрыты тестами. **Реализовано, не проверено E2E:** экранный путь от desktop delivery через review до расчёта и выпуска. **План:** UX-приёмка native flow. **Историческое:** интерфейс не должен показывать extraction как автоматическое подтверждение ролей слоёв.
