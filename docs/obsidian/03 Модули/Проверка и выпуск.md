# Проверка, сохранение и выпуск

## Назначение

Проверить предложенный план, сохранить согласованные изменения
и отдельно контролировать доступность выходных файлов.

## Вход и результат

| Вход | Результат |
|---|---|
| Предпросмотр, текущий проект и правила | Проверенные изменения либо объяснение отказа |
| Подготовленная геометрия | Геометрические замечания и полнота |
| Принятые изменения | Новая версия плана и история |
| Запрос выпуска | Выходные файлы поддерживаемого режима либо отказ |

## Проверка и сохранение

![Проверка и сохранение](../assets/diagrams/03-review-and-save.svg)

1. Получить подтверждённый пользователем предпросмотр.
2. Проверить актуальность проекта, геометрии и правил.
3. Проверить применяемые изменения общим локальным модулем.
4. Сохранить допустимые изменения и историю.
5. Вернуть состояние, которое карта может повторно загрузить.

Запись плана, истории и подтверждения операции выполняется в одной транзакции.
Подтверждение связано с проектом, идентификатором предпросмотра, digest и
исходными версиями. Оно сохраняется после перезапуска и сокращения undo-истории.
GET подтверждения не применяет изменения повторно. Отсутствие подтверждения
не доказывает, что запись не произошла.

Проекты, история и журнал операций используют SQLite. Тестовые проекты в памяти
используют ту же реализацию с базой `:memory:`, без отдельного хранилища на словарях.
Порт истории явно требует атомарного сохранения проекта и подтверждения;
доступность этих методов не определяется во время выполнения через `getattr`.
Проверка версии и запись ревизии принадлежат репозиторию проекта. История,
подтверждения и артефакты добавляются в той же транзакции; ожидаемая версия
запроса меняется только после успешного завершения записи. При отказе записи
версия и время входного проекта восстанавливаются, актуальное содержимое
читается из базы. Публикация полного выпуска обновляет только метаданные проекта,
сохраняя его CAD и план. Формат базы и сохранённых подтверждений не меняется.

Интерфейс различает черновик, выполняемую запись, подтверждённую запись и
неизвестный результат запроса. Если запись подтверждена, но следующее чтение
не удалось, можно закрыть проект или вернуться в библиотеку. Для продолжения
редактирования требуется чтение не старее подтверждённой версии. Одиночная
посадка использует тот же preview и подтверждение, что групповые изменения.
При потере ответа применения посадок проверяется подтверждение операции и затем текущий проект;
автоматического повторения записи нет. Эта гарантия относится к применённым
изменениям. Незавершённый черновик защищается при обычном уходе, но пока не
восстанавливается после аварийного завершения процесса.

Начальная загрузка показывает ожидание, пока чтение не завершено. Состояние
`pending` без выполняющегося запроса не объявляется ошибкой. При отказе чтения
доступно явное повторение. Все потребители кеша проекта, включая помощника,
используют один контракт чтения с проверкой подтверждённых версий.

Undo и Redo возвращают прежнее содержимое с новой, возрастающей версией плана.
История сообщает полный cursor и идентификаторы целей отмены и повтора:
последние 20 видимых записей не ограничивают доступную отмену. Потерянный
ответ команды сверяется с захваченными версиями, конкретной целью и ожидаемым
переходом cursor. Это подтверждает нужное состояние истории; авторство команды
из такого чтения не выводится. Несовпадение оставляет результат неизвестным.

Если проверка не пройдена, сохранение не считается успешным.
Геометрические замечания относятся к конкретным позициям.
Ошибка версии требует нового предпросмотра, а не исправления координат.

## Полнота

Паспорт использует ту же подготовленную геометрию, что и расчёт.
В нём различаются восстановленные области, доступные линии, реальные пропуски
и сознательные исключения.

Сборщик паспорта отдельно читает сведения о слоях, оценивает каждый класс,
собирает замечания захвата и определяет готовность массовой посадки. Отчёт
покрытия запрашивается один раз и проверяется по хешу исходника. Число частей
отображения не становится числом проверенных объектов. При отсутствии этой
возможности у прежнего движка сохраняется оценка импорта. Подтверждённое
исключение остаётся видимым решением и не объявляется пропуском подготовки.

Порядок классов, минимальные основания массовой посадки и уровни уверенности
принадлежат политике паспорта. Объяснения берутся из общего каталога сообщений.
Эта политика не задаёт нормативных расстояний и не изменяет источники документов.

При открытии подготовленного проекта интерфейс один раз показывает спокойное
уведомление о пропусках геометрии. Список слоёв раскрывается по желанию.
«Понятно», закрытие и Escape сохраняют просмотр локально для этого проекта;
API не получает согласие или подтверждение полноты.

Для подготовленного native-снимка с совпадающим хешем исходника общий признак
`SOURCE_GEOMETRY_PARTIAL` не требует отдельного согласия перед посадкой.
Адресные пересечения, нарушения расстояний и неопределённость проверки конкретной
точки остаются в общем проверяющем модуле. Сведения о пропусках и характеристиках
сетей доступны в паспорте; рабочий экран не повторяет их у каждой посадки.
Допуск прежних сохранённых проектов через старый геометрический движок сохраняется.

## Выпуск CAD

Сохранение записывает проект в локальное хранилище.
Выпуск создаёт отдельные выходные файлы. Эти операции не взаимозаменяемы.

Для принятого проекта с архивом захвата создаётся ZIP с отдельным DWG,
доступными подосновами и сведениями о посадках. Исходный чертёж не перезаписывается.

1. Плагин архивирует чертёж того же захвата, на котором основан проект.
   Архив включается в передачу нового проекта. При копировании загруженных XREF
   плагин удерживает блокировку активного
   документа AutoCAD. Если захват уже изменился после неудачной архивации,
   старый проект не выпускается по похожему файлу с диска: нужен новый захват
   и повторная проверка посадок.
2. Фоновый процесс AutoCAD открывает копию и добавляет посадки на новые слои.
3. Результат повторно открывается. Проверяются состав исходных экземпляров,
   ссылки, единицы, количество, идентификаторы, координаты и радиусы посадок.
4. После проверки комплект сохраняется целиком. Ошибка не публикует часть выпуска.

Сборщик комплекта отдельно проверяет пути и происхождение исходников, собирает
объяснения плана, проецирует манифест и описывает готовые артефакты. Имена и байты
ведомости, сцены и SVG задаются один раз; хеши исходников в манифесте повторяют
хеши тех же архивных записей. CSV и ZIP создаёт стандартная библиотека, прогноз
ведомости использует общую типизированную интерполяцию видов. Параметры форматов
принадлежат `releases/config.py`, тексты общему каталогу сообщений, сведения о
нормативном охвате каталогу документов. Эти границы не меняют проверки квитанции
CAD, порядок отказов или публикацию через хранилище.

Архив захвата сохраняется рядом с проектом. Повторный выпуск использует его
и не требует прежнего открытого сеанса. Для первой архивации нового проекта нужен совместимый
плагин и действующая связь с чертежом. Само создание DWG требует установленного
AutoCAD и модуля записи из комплекта приложения.

Измерение, подготовка и выпуск используют общие команды запуска Core и шаблон
CAD-скрипта. Команда выбирается из типизированного перечисления. Подтверждение
завершения измерения и подготовки проверяется по одному контракту: точный состав
полей, три хеша и строго логические признаки освобождения ресурсов. Выпуск
сохраняет отдельное подтверждение записанного результата. Лимиты, отмена и
диагностика каждого сценария остаются его ответственностью.

На macOS локальный API использует модуль выпуска из текущего установленного
GreenAtlasBridge.bundle, если путь к модулю не задан при запуске. Явно
указанный путь имеет приоритет. Совместимость определяется явным контрактом:
worker 0.1.46 обслуживает захват 0.1.46, worker 0.1.47 — захваты 0.1.46 и 0.1.47.
Захват 0.1.47 не допускается к worker 0.1.46. Формат `/1` сохраняет прежнее
чтение; `/2` отдельно передаёт исходный и наследуемый слои. Worker проверяет
класс, исходный слой и преобразование читаемой кривой до расчёта.
Старые резервные копии плагина не выбираются автоматически. Проверки этой
матрицы в рабочей ветке не означают приёмку установленного CAD-выпуска.

Отказ фонового процесса не изменяет сохранённый проект и не запускает выпуск
повторно. Если завершение процесса, полный журнал запуска и его явный отчёт
об ошибке подтверждают остановку до CAD-команд, сообщение указывает на запуск
AutoCAD Core. Ошибка во время команды выпуска и недостаточная диагностика
сохраняют общее сообщение об отказе выпуска. Отсутствие файла результата
само по себе не доказывает, что процесс не запустился. Статус, код завершения
и аргументы отдельного задания сохраняются в его локальном диагностическом
каталоге; окружение и закрытые каналы плагина в этот отчёт не включаются.

Распакуйте весь ZIP и откройте planting-plan.dwg, оставив XREF рядом.
Посадки представлены окружностями с идентификаторами. Полные параметры плана
находятся в green-atlas-plan.json; ведомость входит в полный выпуск.

В Mac-приложении кнопки полного пакета и отдельных файлов запускают загрузку
через системное окно сохранения. CSV и JSON не открываются вместо проекта во
встроенном браузере. Пункт «Файл → К проектам» позволяет вернуться к списку,
если открыта старая страница артефакта. Наличие записи о пакете само по себе
не доказывает, что файл скачался: это проверяется отдельно после сохранения.

На 4 октября установлен Mac desktop/launcher 0.1.53 и plugin/worker 0.1.47.
Свежие передачи Кустанайской и Олимпийской прошли через плагин на копиях
исходников. Для обеих выполнены отдельная подготовка архива через Core,
сохранение непроверенной черновой посадки, холодное открытие и CAD-выпуск
с повторным открытием результата. Неизвестный статус проверки посадок
сохранён. Это проверка хранения и CAD-операций, а не нормативной пригодности
выбранных точек. Пользовательская база и прежний план с 326 посадками
сохранены.

В рабочем коде выпуск строит сцену из уже прочитанного проекта. Манифест
сериализует геометрию по объектам без копии полного дерева GeoJSON;
состав и канонические байты JSON сохраняются. Публикация в одной транзакции
обновляет только версию и время проекта, сохраняя исходник и геометрию.
Конфликт версии и ошибка записи артефакта откатывают весь выпуск.
Эти изменения включены в установленную версию 0.1.53. Чтение свежего
сохранённого проекта и подтверждения операции проверено через установленный
runtime; библиотека открывается без AutoCAD. На большом чертеже расход
памяти при выпуске остаётся высоким, несмотря на уменьшение копирования.

## Черновик и проверенный выпуск

Горизонт расчёта сохраняется в плане, основании проверки и манифесте выпуска.
Год отображения сцены хранится отдельно. Финальный выпуск проверяет свежесть
основания для текущего срока; смена срока не позволяет использовать прежнее
подтверждение. Повторная проверка выполняется локально по тому же снимку.

Повторная проверка использует сохранённую расчётную геометрию, без запросов
каждой посадки в AutoCAD. Если подходящего снимка нет, черновик содержит явное
замечание «без повторной проверки», а финальный выпуск недоступен.
Неполные подосновы и нормативные замечания сохраняются в документах выпуска.
Предупреждения по посадкам не блокируют черновой выпуск и не становятся
автоматически подтверждёнными. Однозначный отказ сервера показывается как
ошибка сборки с сохранением заметок; состояние «исход неизвестен» остаётся
только для потери ответа, когда нельзя доказать, был ли создан пакет.

## Ограничения

- Старый сеанс плагина без архивации нужно обновить; исходник не подменяется
  произвольным DWG с диска.
- Отсутствующие подосновы и шрифты выпуск не восстанавливает.
- CAD-комплект нового входа не является архивом восстановления старого DXF-проекта.

## Ошибка ответа и повторение записи

Непредвиденная ошибка API имеет статус 500 `INTERNAL_ERROR`. Она не доказывает,
что изменение не записалось: сбой может произойти после транзакции. Для посадок
проверяется сохранённое подтверждение по проекту, preview, digest и исходным
версиям. Перезапуск не теряет это подтверждение; повторное применение того же
preview не делает вторую запись. Известные отказы и конфликты остаются адресными.

При неизвестном результате сборки выпуск сохраняет заметки и блокирует
повторную отправку. Снятие сообщения об ошибке и повторное открытие панели
не снимают эту защиту. Для сознательной новой сборки пользователь сбрасывает
настройки и создаёт новое намерение. Если ответ уже содержит идентификатор
выпуска, используется существующее чтение этого результата.

## Завершение фонового CAD-задания на Windows

В кандидате 133 подтверждённый выпуск с кодом Core 0 может завершить оставшиеся
процессы только собственного Job Object. Перед этим проверяются архив, запрос,
worker, Bootstrap, итоговый DWG, подосновы и квитанция выпуска. После очистки
проверки выполняются заново; только затем комплект читается для скачивания.
Сигнал остановки и отдельное подтверждение проверки остаются в `process.json`.
Неполный результат и сторонний процесс не получают исключения из контракта.
При исключении supervisor сохраняется ограниченная квитанция отказа с SHA
журнала, а исходное исключение передаётся вызывающему коду без замены.
