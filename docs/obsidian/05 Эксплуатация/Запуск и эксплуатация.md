# Запуск и эксплуатация

## Локальный запуск

Backend использует Python и `uv`, frontend — pnpm. Базовые команды приведены в корневом `README.md`. На Windows перед каждой сессией разработки обязательно выполняется `. ./scripts/windows-env.ps1`, чтобы временные данные и кеши оставались на диске checkout.

## Контейнерный запуск

`compose.yaml` поднимает:

- `api` с постоянным SQLite volume;
- `web`, доступный локально через Nginx;
- профиль `api-test` для backend-проверок.

API и web собираются отдельными Docker targets. API имеет healthcheck-зависимость для web и корректный grace period остановки.

## Развёрнутая площадка

Исторически площадка размещена на AdminVPS. Доступ закрыт HTTP Basic, TLS завершается на Nginx. Агент отключён до подключения model API. Текущее состояние сервера должно проверяться отдельно: репозиторий не является доказательством работающего deployment.

## Диагностика

1. Проверить `/api/health`.
2. Проверить доступность SQLite path и свободное место.
3. Проверить protocol `0.1.33` и очередь `v033`, не смешаны ли старые bundle.
4. Проверить evidence, coverage, source/XREF SHA-256 и admission issue.
5. Проверить последнюю фоновую operation проекта и отдельно semantic mappings.
6. Сопоставить `state_version` клиента и сервера.
7. Не закрывать и не сохранять чужую открытую AutoCAD-сессию ради extraction.

## Восстановление

- неудачная повторная загрузка не должна заменять существующий проект;
- native residual instances не удаляются: они остаются в coverage и review;
- rejected native probe не заменяется скрытым fallback parser;
- undo/redo хранится в SQLite;
- опубликованный выпуск остаётся неизменным;
- удаление проекта является необратимой пользовательской операцией.
