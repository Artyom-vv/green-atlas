# Запуск и эксплуатация

## Условия работы

Нужны совместимые AutoCAD, плагин и локальное приложение Green Atlas,
доступ к чертежу и его подосновам, место для проекта и подготовленной геометрии.
Mac-пакет требует Apple Silicon, macOS 14 или новее и полный AutoCAD 2027.
Порог macOS 14 согласован с нативным плагином и требованиями AutoCAD, но
сквозной запуск на macOS 14 и 15 пока не принят на отдельном устройстве.
Python, Node.js и Rosetta для Green Atlas не требуются: CAD-выпуск использует
нативный ARM-компонент AutoCAD. AutoCAD устанавливается отдельно.

Проверенная среда указана в [[00 Обзор/Текущее состояние|статусе возможностей]].
Сборка исходного кода не означает обновления уже установленного приложения.

Для Windows опубликован отдельный прототип 0.1.42 в `submission/prototype`:
Windows 11 x64, полный AutoCAD 2027 и Microsoft Edge WebView2 Runtime.
Распаковать весь ZIP, закрыть приложения и запустить `Install-GreenAtlas.cmd`.
Python и Node.js включать или устанавливать пользователю не нужно.
CAD-архив общий с Mac, открытие выполняется через `GAOPEN`.
Первый CAD-выпуск требует открытого исходного сеанса AutoCAD.
361 файл Windows-bundle проверен по manifest; сквозной запуск на стенде
описан в README прототипа. Чистая Windows-машина пока не принята.
Windows-пакет не содержит последние Mac-правки 0.1.45; ветки кода при публикации
архива не объединяются. Установка и ограничения описаны отдельно для платформ.

## Начало работы

1. Подготовить рабочую копию чертежа и доступных подоснов.
2. Открыть корневой DWG/DXF в AutoCAD.
3. На листе `1` проверить, что виден полный чертёж, а не только контур;
   проверить загруженные XREF и завершить ожидающие ответа диалоги AutoCAD.
4. Запустить Green Atlas через плагин.
5. Проверить слои, границу и замечания.
6. Выполнить подготовку карты.
7. Перейти к выбору участка и посадкам.

В основном сценарии пользователь не вводит адрес локального API
и не загружает чертёж через отдельный конвертер.

## Хранение и резервирование

Проект хранится в SQLite. Подготовленная геометрия хранится рядом с базой
в каталоге, имя которого образовано из пути базы и суффикса .prepared-geometry.
Эти данные следует резервировать совместно.

Каталог .cad-archives рядом с базой хранит подоснову для повторного CAD-выпуска;
его также включают в резервную копию. .layer-recognition содержит предложения
модели, которые можно получить повторно. .cad-release-jobs хранит рабочие файлы
и диагностику выпуска.

Для согласованной файловой копии нужно завершить запись и закрыть приложение.
Нельзя копировать только основной файл открытой SQLite, игнорируя её журнал,
или удалять каталог геометрии как необязательный кеш.

Готовый снимок не зависит от временного процесса AutoCAD.
Если снимок отсутствует или устарел, повторная подготовка требует AutoCAD.

## Диагностика

| Симптом | Что проверить | Следующее действие |
|---|---|---|
| Приложение не запускается | Совместимость пакета, журнал, наличие ресурсов | Восстановить комплект приложения |
| macOS блокирует установщик | Проверить источник и SHA-256 архива, затем сообщение защиты macOS | При доверии к архиву использовать «Конфиденциальность и безопасность» → «Всё равно открыть» только для этого приложения; не отключать системную защиту |
| Установщик сообщает об отсутствии совместимого приложения | Проверить полный архив, подпись и запуск из карантинного пути Finder | Распаковать новый полный пакет и повторить; не подменять отдельные файлы внутри `.app` |
| Установщик не принимает систему | Версию macOS и архитектуру Mac | Для этой сборки нужны Apple Silicon и macOS 14 или новее |
| Команда не появилась после установки | Полный ли это AutoCAD 2027 и был ли он перезапущен | Закрыть и заново открыть AutoCAD; если macOS блокирует плагин, сообщить точную ошибку |
| В `Model` только контур | Как выглядит лист `1` | Перейти на лист `1`; такой вид `Model` сам по себе не доказывает потери данных |
| Лист `1` пуст | В Reference Manager проверить загрузку XREF и каталог `00.3_Ссылки` рядом с генпланом; отдельно проверить видимость слоёв и изоляцию объектов | Если XREF загружены, восстановить видимость; если нет, обновить ссылки. При сомнении закрыть без сохранения и вновь открыть полный комплект. Не готовить карту с пустым видом; один отсутствующий исходный `I7 чб` не объясняет исчезновения остальных ссылок |
| Чертёж не передаётся | Доступность XREF, версию, размер и целостность | Устранить причину и повторить передачу |
| «Не удалось принять снимок» в сборке 0.1.43 | Плагин выдаёт версию 0.1.43, которую API этой сборки не принимает | Установить полный Mac-комплект 0.1.45, перезапустить AutoCAD и Green Atlas и повторить команду; исходный DWG не менять |
| Слои не сохраняются | Назначение и конкретные ошибки полей | Исправить несовместимое назначение |
| Связь с чертежом устарела | Нужна ли новая подготовка или CAD-коррекция | Открыть исходник и восстановить связь |
| Подготовка долгая | Стадию операции и её счётчики | Дождаться результата или явно отменить |
| Не хватает мест | Область поиска, препятствия, замечания и причину остановки | Скорректировать данные или параметры |
| Предпросмотр устарел | Изменения проекта после его создания | Сформировать новый вариант |
| CAD-выпуск недоступен | Полный AutoCAD 2027, комплект приложения, архив захвата и связь с AutoCAD | Обновить совместимый комплект; для первой архивации открыть исходный чертёж. Нестандартный путь к AutoCAD задаётся через `GREEN_ATLAS_AUTOCAD_ROOT` |

Повтор запроса не исправляет отсутствующий файл ресурсов.
Не следует обходить ошибки подменой контрольных сумм либо массовым
исключением физических слоёв.

## Сохранность исходника

Приложение не перезаписывает исходный DWG. Захват может изменить DBMOD —
признак изменений в открытом AutoCAD. Решение о сохранении такого документа
принимается отдельно. Пользовательские посадки не удаляются ради повторного
испытания: для него создаётся другой проект.

## Подключение распознавания слоёв

Настройка GREEN_ATLAS_LAYER_MODEL_PROVIDER принимает четыре значения:

| Значение | Работа |
|---|---|
| auto | OpenAI при наличии ключа, иначе сохранённые предложения для точного исходника или распознавание по названиям |
| openai | Запросы модели через Responses API; нужен OPENAI_API_KEY на стороне сервиса |
| codex | Локальный запуск Codex CLI с моделью gpt-6-luna; нужен вход в Codex |
| names | Только правила названий, без внешней модели |

Локальное приложение по умолчанию использует auto, отдельный API — names.

Таблица описывает настройку кода соответствующего checkout, а не обещание
готового доступа во всех установщиках. Mac 0.1.45 содержит клиент relay,
но URL и токен выдаются и настраиваются отдельно. Windows 0.1.42 этого
клиента не содержит. Серверная реализация находится в рабочем dev,
не в публичном main. Обе платформы используют включённые предложения
для неизменённой Кустанайской без серверного запроса или личного ключа.

Автоматического перехода на локальную сессию Codex нет. Режим `codex`
остаётся только явной настройкой разработчика.

Для воспроизводимой демонстрации можно включить готовые предложения OpenAI
без ключей и платных запросов на компьютере проверяющего:

```bash
python scripts/export-layer-recognition-preset.py \
  --database /path/to/projects.sqlite3 \
  --project-id PROJECT_ID \
  --destination /path/to/recognition-presets
GREEN_ATLAS_LAYER_RECOGNITION_PRESETS=/path/to/recognition-presets \
  bash tools/autocad-bridge/build-desktop-macos.sh /path/to/GreenAtlasRuntime
```

Экспортируется только завершённый ответ для текущей версии классификатора.
Сборка помещает его в `Resources/LayerRecognition`. Ответ привязан к SHA-256
исходного DWG и точному составу слоёв, но не к пути файла или локальному
снимку AutoCAD. При изменении исходника или слоёв ответ не используется.
Предложения не подтверждают слои за пользователя. В архив не добавляют каталог
личных настроек `AI`, ключи, прокси-пароли и журнал расходов.
Путь к CLI можно задать через GREEN_ATLAS_CODEX_EXECUTABLE. Старый CLI,
не поддерживающий выбранную модель, нужно обновить. Провайдер и ошибки видны
в разделе слоёв. Ключ не передаётся браузеру и не хранится в проекте.

OpenAI использует `gpt-6-luna`, стандартный тариф и структурированный ответ.
В модель отправляются только названия слоёв, идентификаторы, количества и типы
объектов. Геометрия и чертёж остаются локально. Подробный предложенный тип
применяется при подтверждении группы; сохранённые решения не перезаписываются.
Неизвестный слой не считается подтверждённым исключением.

### Ключ, прокси и бюджет

Ключ не входит в установщик. Для локальной настройки разработчик запускает
`scripts/configure-layer-api.py --env-file <приватный env-файл>` через Python
окружения API. Файл должен содержать `OPENAI_API_KEY` и, при необходимости,
`OPENAI_PROXY_URL` со схемой `socks5` или `socks5h`. Прямого повторного запроса
при отказе прокси нет. Настройка сохраняется с правами владельца в пользовательской
папке Green Atlas/AI, вне проекта. На macOS это
`~/Library/Application Support/Green Atlas/AI`.

Все проекты и процессы одного пользователя используют общий журнал `budget.sqlite3`.
Общий лимит составляет $2, без сброса при перезапуске или обновлении приложения.
Перед отправкой атомарно резервируется консервативная верхняя оценка стоимости
входа и максимального ответа. Резерв не возвращается даже после сетевой ошибки;
реальное количество токенов сохраняется отдельно. Поэтому бюджет может остановить
запросы раньше фактического расхода $2. Повреждённый или пропавший журнал
останавливает запросы, а не создаётся заново автоматически.

Это ограничение запросов данной установки для текущей разработки, а не лимит
всего аккаунта OpenAI. Для прототипа готовые предложения встроены в
приложение, поэтому ключ проверяющему не нужен. Личный ключ нельзя
распространять с прототипом.
Повторный показ готовых предложений использует кеш. Ошибка авторизации или
исчерпание бюджета отображаются в разделе слоёв без содержимого ключа.

## Проверка установки

Самотест установщика включает исходник через символическую ссылку на родительский
каталог: Finder может перенести скачанное приложение в такой путь. Ссылки
внутри вложенного приложения при этом остаются запрещены. Самотест не заменяет
проверку запуска из Finder на чистой машине.

При сборке Mac-комплекта одного `LSMinimumSystemVersion=14.0` недостаточно:
встроенный Python и нативные библиотеки должны иметь собственный минимальный
уровень macOS не выше 14. Скрипт сборки runtime проверяет вложенные Mach-O-файлы
и останавливается, если Python с машины разработчика требует macOS 26.
Это проверка бинарников, а не результат запуска на реальной macOS 14 или 15.

Проверяются запуск без исходного checkout, наличие справочника и правил,
передача из AutoCAD, подготовка, контроль запрещённых точек, сохранение,
повторное открытие и отдельный холодный запуск.
Проверка упакованного API может использовать изолированную копию базы с
подготовленной Кустанайской: `test_frozen_runtime_saves_automatic_planting`
выполняет автоподбор, применение результата и повторный запуск того же
исполняемого файла. Для неё задаются `GREEN_ATLAS_FROZEN_RUNTIME`,
`GREEN_ATLAS_PREPARED_DB` и `GREEN_ATLAS_PREPARED_PROJECT_ID`. Исходная база
не изменяется. Такой тест не заменяет прогон действий в установленном окне.

Инструкция по сборке для разработчика находится в корневом README репозитория.
Для Windows-команд разработки предварительно применяется
scripts/windows-env.ps1 в той же PowerShell-сессии.
